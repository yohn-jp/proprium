# Semantic BGE reranker component

This isolated component implements the canonical fp32 `mogolloni/bge-reranker-v2-m3-onnx` model pinned in the Semantic canon. It does not change the E5 component or the generic Host WIT.

The outer Semantic guest uses the existing `workspace.asset.read` capability to fetch the small ONNX graph, then asks `inspect-graph` for its exact external tensor ranges. It fetches 256 KiB ranges from the separately admitted signed BGE asset group in ascending file-offset order, at no more than 64 Host range reads per scheduled action. It sends tensor pieces to this component as they arrive. The component hashes the complete external-data file as ranges arrive and rejects any mismatch against the pinned digest. During parse, its custom tract resolver moves each owned tensor buffer into tract so the full external-data file is never held as one additional monolithic allocation.

The exported WIT is deliberately component-local. Caller authorization, consent-gated asset admission, host-side range verification, task cancellation and worker lifecycle remain in the existing Host path. No model weights are committed to this repository.

The source pins, provenance and exact per-file hashes are recorded in [model-source.json](model-source.json). The registry producer must create the signed optional asset group from these files before product enablement; this file is provenance metadata, not an admission signature.

The exact fp32 graph passed a native tract parse/score smoke and a Node 24.21.0 run of the jco 1.39.0 transpiled wasm32 component. The paired scores were finite, repeatable and ranked the matching passage higher. The component's WASM linear memory reached 3,540,385,792 bytes after model load and scoring. The browser scheduler and signed group build path are now present in source; build-and-sign, browser memory, cancellation/reload and real-host inference checks remain unverified. Mobile and WebKit support are not claimed. Quantized or differently sourced weights require a separate product decision and model identity.

To reproduce the Node/WASM smoke, first download the three exact files listed in `model-source.json`. Build from `plugins/semantic` so its shared `.cargo/config.toml` applies: `cargo component build --manifest-path reranker/Cargo.toml --target wasm32-unknown-unknown --release --locked`. That config selects getrandom's `unsupported` backend for WASM because reranker inference is deterministic and has no ambient entropy capability; do not enable a JavaScript/Web Crypto import. Transpile the component with `jco transpile`, then run `node reranker/scripts/wasm-smoke.mjs <transpiled-component.js> <model.onnx> <model.onnx_data> <tokenizer.json>`. The script checks the pinned graph identity, streams the external ranges in 256 KiB chunks, and reports component linear-memory and Node RSS measurements. It requires Node and jco and does not exercise Host asset reads or browser memory limits.
