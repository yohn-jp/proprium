# Wave 0: all 64 audit candidates

IDs C01–C64 follow the source-table order in [CORE-PERFORMANCE-AUDIT.md](../architecture/CORE-PERFORMANCE-AUDIT.md). No candidate is implemented here. `Observed` describes the named workload or counter, never an unperformed optimization or causal proof. `Hypothesis` and `NOT_CHECKED` remain separate from observed cost.

`G` refers to the [checked-in summary](results/2026-10-20/summary.json) → `core` and the corresponding raw Core result/native Git trace. `B` refers to `browser` and raw browser phases/CPU profile. [BASELINE.md](BASELINE.md) defines artifact provenance, complete/partial scales and units. Missing/timed-out operations are NOT_CHECKED even where a whole workload is requested.

Updated priorities: W1-A input materialization investigation; W1-B React subscriptions; W1-C incremental journal refresh; W1-D cold revision reads. Exactly four ledger candidates are proposed: C01, C04, C13 and C22. Related entries are context only; they are not additional Wave 1 work. These four are proposed experiments only. “Investigate” follows these; “Measure next” lacks sufficient evidence; “Defer” has weak measured performance benefit or large design scope; “Invariant” is protected behavior.
