## C55 — late callback failed the abort invariant

The focused test reached the real host’s deferred author-change path. Before resolving the old mount, assertions passed that the mount authors were `author-old` then `author-new`, the old signal had aborted, the new contribution had one active set of resources, and the deferred old mount had not yet disposed. After resolving the old mount, the callback attempt completed and dispose ran. The assertion expected the callback outcome `rejected`, but the browser reported `resolved`.

The fixture’s `journalWrites` assertion followed the failing outcome assertion, so Playwright did not emit the captured metrics array. The observed callback result establishes that the old callback was not rejected after abort. Source inspection shows the in-process write path it takes: `context.propose` calls `journal.putProposal(snapshot.repository, authorScope, submitted)` before awaiting the API, then journals the API result using that same captured scope. The route fulfills the proposal request successfully. It is therefore an inference from the executed resolution and source order that the callback wrote into `author-old`; this run did not preserve an emitted write count. The harness has since been adjusted to attach all metrics before any assertion, so a follow-up run can show the array directly.
