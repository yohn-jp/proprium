# Core-64 static delivery baseline observations

Date: 2026-10-21. The API/runtime source is `1a03807dec4990c7b44af551b4dcbd279c9498e4`; the UI artifact is the archived G5 baseline built from `9f801061d1cc40c4719988b5e1aef17d3ff60e74`. The UI source predates C39 in the current API/runtime tree. These results establish current handler counts and browser cache behavior only. They are not the matched before sample for the C47 candidate.

The G5 Core and Full UI directories were checked against the archived G5 artifact hashes before serving. No C59 output was used. The runtime was built from the current source after `pnpm install --frozen-lockfile`; Node was `v24.21.0`, pnpm `12.10.1`, and the frozen lockfile SHA-256 was `107821c3fdeb50571c891e7de500c0b477bc01206c1f4caa63d830fd8be7e768`. The API, Core, and module-runtime build hashes, exact UI hashes, probe hash, runtime details, and raw samples are in [`core.json`](./core.json) and [`full.json`](./full.json). The task-local probe is [`core64-static.mjs`](../../../../../scripts/performance/core64-static.mjs).

For each profile, one warm-up GET was followed by 1,000 sequential GETs of the root launcher `/main.js`. All 1,000 returned HTTP 200 and the exact verified artifact bytes. The process-local `fs/promises` wrapper counted 1,000 `lstat`, 2,000 `realpath`, and 1,000 `readFile` calls for the static root. The `/proc/self/io` counters are recorded separately; they cover the whole server process during the sample and are not a count of every filesystem syscall. Core read 723,541,000 asset bytes across requests; Full read 726,390,000.

The measured Core TTFB distribution was p50/p95/p99 `5.13/11.17/18.05 ms`; Full was `5.67/12.45/21.65 ms`. Host processes were active on other CPU cores during this semantic/count run, so these latency values are observational and are not a controlled comparison. The later before/after sample must use the same current source, profile, lock, runtime build, browser, CPU affinity, and UI artifact inputs; timing gains cannot be inferred from these numbers.

The probe then navigated one browser context to `/`, `/desktop/`, and `/mobile/`, twice per route, clearing Resource Timing entries between navigations. Core transfer bytes (document plus app JS/CSS) were `753,354/753,354`, `803,535/803,535`, and `1,735,364/1,735,364`. Full was `756,203/756,203`, `806,394/806,394`, and `1,737,079/1,737,079`. All six first/repeat pairs returned 200, exposed `Cache-Control: no-store`, had a CSP header, and used distinct request-specific style nonces. Repeated loads saved zero app transfer bytes. An implicit missing `/favicon.ico` request was excluded because it is not referenced by the application HTML.

The current API static-handler test already covers desktop/mobile routes, fixed `main.js` compatibility, deep routes, missing assets and unknown paths returning 404, a symlinked asset escaping the static tree returning 404, fresh shell nonce/CSP, MIME type, and API fallthrough. Those tests were inspected but not run in this baseline-only phase. This observation does not verify an old open client's hashed lazy chunk across a deployment or rollback. The next candidate must preserve the existing path and symlink checks, fixed-name aliases, nonce/CSP behavior, and 404 behavior, then test cache headers only for content-hash-named entry assets.
