# Core 64 G1 C06 / C11 decision

Decision date: 2026-10-21. Runtime source: `a1587e784788fa87d86c0eb7ab175d7a28a3209f`; planning base: `7008feef2294e1176cda2799ec0384e4ee7585c0`. The implementation files cited below match the runtime SHA. This records **no-change deferrals** for C06 and C11; it does not close C04, C07, or C08.

## C06 — defer broad `SharedApplication` decomposition

`AuthorWorkspace` owns the coupled editor and recovery session, not just view composition: React `work` state and authoritative `workRef`, navigation and scene-load epochs, draft generation, current author scope, draft timers, pending entries, and the serialized journal queue are declared together ([state and refs](../../../../app/src/application/SharedApplication.tsx#L398)). The W1 path updates `workRef` immediately while it may coalesce React publication; `editText` still creates the generation-bound `ChangeOperation` and retains the 350 ms draft schedule ([publication boundary](../../../../app/src/application/SharedApplication.tsx#L476), [edit path](../../../../app/src/application/SharedApplication.tsx#L1618)). Moving this code into another component or hook would not remove operation creation, generation checks, publication, or the write schedule.

Scene navigation is guarded across asynchronous boundaries. `loadScene` captures navigation and scene-request epochs plus author scope, flushes CodeMirror composition and the latest recoverable draft before its read, verifies that remote and effective views use the pinned snapshot, and checks that the captured context remains current after storage/receipt awaits ([load guard and flush](../../../../app/src/application/SharedApplication.tsx#L905)). Draft persistence serializes queued writes, and its caller only publishes completion into the matching navigation, author, operation, and text; `putLatestDraft` validates the operation, uses a strict read/write transaction, rejects newer or conflicting generations, and waits for transaction completion ([write caller](../../../../app/src/application/SharedApplication.tsx#L1563), [journal implementation](../../../../app/src/storage/journal.ts#L234)). `flushDraft` loops against the live editor until the current text is recoverable before navigation or another protected action ([flush loop](../../../../app/src/application/SharedApplication.tsx#L1661)).

Remote restore has a similarly captured binding. It drains composition and queued writes, captures project/repository/document/scene/author plus operation ID and generation, deletes only same-author draft entries in a strict transaction, then verifies that the live editor still matches the captured operation before replacing its text. If the draft changed during removal, it preserves or re-persists the newer text ([restore path](../../../../app/src/application/SharedApplication.tsx#L2020), [draft-only removal](../../../../app/src/storage/journal.ts#L595)). The `beforeunload` path also blocks navigation while a draft is unconfirmed and starts only best-effort persistence during cleanup; extraction must not turn that into a durability claim ([unload handling](../../../../app/src/application/SharedApplication.tsx#L1414)).

The G0 aggregate React/fiber and Long Task results do not identify a component duration or state-owner cost. A broad split would relocate the coupled work above without removing it, and would risk weakening its generation, author-scope, scene freshness, and recovery relationships. **Disposition: defer C06 with no code change.** Reopen it only if a matched profile identifies a small boundary with a measurable cost; scope any implementation to that leaf and retain the current guards.

## C11 — defer `SceneEditor` decomposition or lazy view loading

`SceneEditor` statically imports the history panel, reading pager, CodeMirror input, and preview renderers; it owns pending editor text, composition-flush registration, reading state, typography state, and selection state ([imports](../../../../app/src/editor/SceneEditor.tsx#L5), [state and pending-text handling](../../../../app/src/editor/SceneEditor.tsx#L218)). Resume restoration uses the live editor ref to restore cursor/scroll position and focus; print flushes the pending React publication before invoking the browser print flow ([resume lifecycle](../../../../app/src/editor/SceneEditor.tsx#L247), [print flow](../../../../app/src/editor/SceneEditor.tsx#L289)). The parent keys the editor instance by author, repository, document path, and write permission and passes its durability, history, resume, navigation, and current-text contracts ([parent binding](../../../../app/src/application/SharedApplication.tsx#L2458)). A file split alone would not reduce reconciliation; lazy loading could trade startup bytes for first-use delay.

The current UI already gives reading and inline history conditional mount paths, but keeps CodeMirror mounted in the hidden editor columns during reading mode. Preview, scratch, print, and history paths all consume the current scene/text identity ([view composition](../../../../app/src/editor/SceneEditor.tsx#L372)). History also exists as a separate Workspace panel. Workspace invokes the selected panel’s render function ([panel content](../../../../app/src/workspace/Workspace.tsx#L80)); optional contribution modules use their own generated loader and selected-instance abort/dispose lifecycle ([ContributionHost.tsx](../../../../app/src/contributions/ContributionHost.tsx#L39)). C11 does not authorize changing those module semantics.

G0's asset report has aggregate bytes only: desktop JavaScript is 753,221 bytes (239,035 gzip), and mobile JavaScript totals 1,688,058 bytes (441,189 gzip). It does not attribute bytes to `SceneEditor` or its optional views. G0 also has no component `actualDuration` or first-open timing. **Disposition: defer C11 with no code change.** Reopen only when a per-view source map or first-use trace isolates cost and a matched A/B demonstrates a startup benefit without an unacceptable first-use delay or CodeMirror remount.

## Remaining render work

C04, C07, and C08 now have a matched instrumented attribution on the C02-integrated runtime; the decision and limitations are in the [G1 render report](../../CORE-64-RENDER.md#matched-g1-attribution). No local production optimization was adopted: C04's Editor subtree dominates the flagged fibers but has no measured component duration or isolated state-owner seam; C07 panel references change on some parent renders without evidence that stabilizing them removes the parent work; C08's five-entry derivations are at or below 0.1 ms timer resolution.
