# Hosted producer attestation

`scripts/hosted-attestation.mjs` prepares the in-toto Statement v1 consumed by Praetorium and signs it with the upstream Sigstore CLI. It does not create signing keys or change the release workflow. The producer checkout must be clean, `origin` must resolve to `yohn-jp/scriptorium`, both OCI references must be immutable, and the supplied canonical sidecars must describe that exact source revision and image digests.

The statement has exactly three subjects: the Runtime Base image digest, `scriptorium-build/v1/catalog.json`, and `scriptorium-platform/v1/runtime-metadata.json`. Its SLSA v1 materials bind the clean Git commit, catalog source/recipe/lock digests, and Build Kit image digest. Praetorium verifies the metadata-subject digests against its strict schemas and verifies the Sigstore DSSE bundle under the configured public-good trust root and source identity allowlist.

First build the existing producer validators, generate the catalog sidecar for the immutable Runtime Base/Build Kit pair, and build the Core composition from those same inputs. The Runtime Base image does not contain the hosted sidecars; retrieve the canonical runtime metadata from that immutable Core composition, which embeds the producer metadata generated by the Build Kit. Keep the bytes unchanged:

```sh
corepack pnpm@12.10.1 install --frozen-lockfile
corepack pnpm@12.10.1 build

REVISION="$(git rev-parse HEAD)"
RUNTIME_BASE_IMAGE='ghcr.io/yohn-jp/scriptorium/runtime-base@sha256:<runtime-base-digest>'
BUILD_KIT_IMAGE='ghcr.io/yohn-jp/scriptorium/build-kit@sha256:<build-kit-digest>'
CORE_IMAGE='ghcr.io/yohn-jp/scriptorium/core@sha256:<core-composition-digest>'
RUNTIME_BASE_DIGEST="${RUNTIME_BASE_IMAGE##*@}"
BUILD_KIT_DIGEST="${BUILD_KIT_IMAGE##*@}"
COSIGN_BIN='/usr/local/bin/cosign'
COSIGN_VERSION='<exact-pinned-version>'
COSIGN_SHA256='sha256:<sha256-of-cosign-binary>'

node scripts/hosted-build.mjs catalog \
  --producer-revision "$REVISION" \
  --runtime-base-digest "$RUNTIME_BASE_DIGEST" \
  --build-kit-digest "$BUILD_KIT_DIGEST" \
  --out /tmp/scriptorium-build-catalog.json

docker run --rm --entrypoint node "$CORE_IMAGE" \
  -e 'process.stdout.write(require("node:fs").readFileSync(process.argv[1]))' \
  /usr/share/scriptorium/runtime-metadata.json \
  > /tmp/scriptorium-runtime-metadata.json
```

Use an operator-provided pinned Cosign v2.6.5+ or v3.1.3+ binary that supports `attest-blob --statement` and `verify-blob-attestation`, plus the exact certificate SAN and OIDC issuer already allowed by Praetorium's release policy. The script rejects earlier and prerelease versions affected by GHSA-fx35-mq7g-6g98. It explicitly requests the standardized Sigstore protobuf v0.3 bundle, which Praetorium's `@sigstore/bundle` consumer parses. Cosign uses its normal keyless OIDC provider; no private key option is accepted. The command leaves the canonical statement on disk if OIDC is unavailable, but it never emits a successful bundle unless Cosign creates one and verifies its signature, certificate identity, transparency evidence, statement bytes, and catalog subject.

```sh
node scripts/hosted-attestation.mjs attest \
  --catalog /tmp/scriptorium-build-catalog.json \
  --runtime-metadata /tmp/scriptorium-runtime-metadata.json \
  --runtime-base-image "$RUNTIME_BASE_IMAGE" \
  --build-kit-image "$BUILD_KIT_IMAGE" \
  --statement-out /tmp/scriptorium-provenance.statement.json \
  --bundle-out /tmp/scriptorium-provenance.sigstore.json \
  --cosign-bin "$COSIGN_BIN" \
  --cosign-version "$COSIGN_VERSION" \
  --cosign-sha256 "$COSIGN_SHA256" \
  --certificate-identity '<allowlisted-certificate-SAN>' \
  --certificate-oidc-issuer '<allowlisted-OIDC-issuer>'
```

To make the result retrievable through Praetorium's HTTPS `signatureRef`, the owner-controlled registry endpoint must accept an immutable authenticated `PUT` with `If-None-Match: *`, then return the exact bytes from `GET`. Supply that pre-provisioned endpoint and a token environment-variable name when running `attest`; the script checks readback byte-for-byte. It does not create a release or publish on its own:

```sh
export SCRIPTORIUM_RELEASE_REGISTRY_TOKEN='<owner-issued-upload-token>'
# Add to the attest command:
--publish-url 'https://<owner-registry>/scriptorium/<revision>/provenance.sigstore.json' \
--registry-token-env SCRIPTORIUM_RELEASE_REGISTRY_TOKEN
```

Record the returned HTTPS `signatureRef` and the separate provenance reference required by the existing Praetorium release candidate. The registry must serve the bundle bytes directly without redirects or transformation. A signing identity, OIDC issuer, or upload credential that is absent from the owner environment remains an external release gate; statement generation and local conformance checks do not count as a signed release.
