# Canon P1 — proprium.research (Search, Terminology and Lightweight NLP)

**Status: normative recovery and implementation contract.** This document specifies a target WASM plugin. Scriptorium modules are source evidence, not a shipped Proprium plugin. **RECOVERY** means observable behavior present in the cited implementation/UI; **DESIGN_TARGET** means behavior required here to complete the Proprium author workflow or close a documented migration gap.

## 1. Product role and boundary

Research helps an author find a passage, term, or prior usage in a Git workspace and return to the same writing context. It provides deterministic lexical search, a reviewable terminology registry, manuscript text analysis, and optional local Japanese morphology. It works without a model, network, Gateway, login, Narrative, Knowledge or Semantic plugin. The first search query must work on locally available workspace files without downloading an asset.

Research defines and uses derived text indexes and its terminology and synonym/candidate preference files. It does not own manuscript text, scene identity, entity/Bible schemas, editor buffers, Git writes, plugin grants, model distribution trust, embeddings, or publication. Search and term navigation call Host navigation; changing a registry or author preference creates a ChangeSet for Host review and apply. Research never writes files itself.

The sole official product boundary is one **proprium.research** plugin. Its small search and term UI ships with the plugin; bounded Japanese tokenization is a lazy optional component/capability within that product. Do not make an NLP-only top-level plugin. Embeddings and semantic reranking remain in optional **proprium.semantic**, with Research retaining the single search surface. Knowledge owns entity creation and semantic identities; Research may provide candidate evidence but cannot create or mutate a Knowledge entity.

## 3. Data contract and ownership

Research operates on the Host's repository-scoped, revision-pinned snapshot. It enumerates only text roots declared below; it never assumes that a repository is a novel and returns ordinary files/search results when Narrative is absent. For scene labels or semantic scene IDs, the Host may compose the public `proprium.narrative.hierarchy.tree` action with the same snapshot (`parent_id`, `cursor`, `limit` up to 200); it uses each returned `manuscript_path` and obtains that file revision through the same pinned Host file reader. The hierarchy page does not read or promise body revisions for every scene. This is optional decoration only; a path-based result remains useful without Narrative. For structured entities the Host may provide a page from `knowledge.entities.list` and `knowledge.entities.get`. Research never calls another plugin or parses private Knowledge/Narrative internals.

The legacy term writer currently serializes a narrowed schema-1 object and can drop unknown extension keys. Proprium's target writer must retain them; this is a concrete recovery gap, not a claim that the old writer already passes preservation. Do not perform a bulk rewrite or silently migrate .arcadia/, meta/synonyms.yaml, or other paths. If a separately authorized importer encounters those Loom paths, it must preview and preserve originals under the migration contract; Research does not search or rewrite them implicitly.

All offsets crossing the ABI are zero-based UTF-16 code-unit offsets into the exact source string associated with its textRevision. Normalization (NFKC, case folding) happens only in derived match keys; the span map returns original offsets. Unicode normalization, ruby syntax, Japanese punctuation, surrogate pairs and active IME composition must not change stored prose. Research decorations are ephemeral Host UI state.

## 4. Public actions and error semantics

Every call uses H0 ActionRequest: request_id, plugin_id, stable action_id, schema_version 1, scope, pinned snapshot, strict schema-validated input, deadline_ms and optional idempotency_key. Caller and activation epoch are Host-supplied. Every result uses the common ActionResult envelope: {ok:true,request_id,scope,snapshot,value,warnings} or {ok:false,request_id,scope,snapshot,error:{code,message,retryable,details?}}. Payloads described in the tables below are inside value. Unknown input fields fail invalid_input. The Host rejects a response for another workspace, snapshot, activation epoch or expired request. A read action may perform bounded search/index/tokenization and write only disposable derived cache; it cannot create canonical files or proposals. A propose action returns a Host-owned ChangeSet reference and preview; only Host review and Apply mutate the local worktree.

Search modes preserve Scriptorium behavior and fix the incomplete result contract. Normalize match keys with NFKC + lowercase. Tokenize letter/number/underscore runs; Japanese kana/kanji runs contribute adjacent character bigrams (a one-character run contributes that character). `lexical` document points are: exact normalized path 120, exact normalized basename title 110, path contains query 85, body contains query 65, all query tokens present 30 + query-token count. With morphologyHints, add a candidate at max(current score, 45 + number of unique local noun hints) only when every hint occurs in the body. `prefix` points: path prefix 80, body prefix 35, any indexed token prefix 25. `exact` points: exact path/title 100, complete body phrase 65. Term hits score exact spelling 1000, prefix spelling 500, other lexical spelling 250. `scoreFactors` is a subset of `path-exact`, `title-exact`, `path-contains`, `body-contains`, `all-query-tokens`, `morphology-hints`, `prefix-path`, `prefix-body`, `prefix-token`, `body-phrase`, `term-exact`, `term-prefix` and `term-lexical`; these points rank one mode and are not probabilities. Sort ties by normalized path, normalized title, kind (`document` before `term`), then term ID using Unicode code-point order, independent of device locale. Search term hits require an available target and use its pinned file revision. The exact phrase/body behavior and bounded opaque cursor are DESIGN_TARGET completions: the legacy exact mode checked only title/path/term equality and the action had no reliable page continuation. Results carry enough source evidence to reproduce a jump. The legacy includeSemantic flag is handled by Host composition of the same UI with `proprium.semantic.passages.query` and optionally `proprium.semantic.rerank`; Research does not call another plugin directly.

Candidate discovery reproduces the source rule: join each maximal adjacent run of tokens whose POS is exactly `名詞`; concatenate surfaces and concatenate readings only if every token has one. Keep runs of at least two UTF-16 code units that are not solely whitespace, punctuation, symbols or digits, and drop exact known-term matches. Count every occurrence across the item's text records, but list each `sourceId` once. Evidence reports each occurrence range in the exact text record, capped at five samples per candidate; `occurrenceCount` remains the full count. Choose the first non-null reading in caller corpus order and sort the complete result by occurrence count descending then term code-point ascending before cursor paging. An unavailable tokenizer fails only this action; it never returns approximate noun candidates as exact analysis.

Term variant similarity follows `shouldClusterByString`: strings cluster when one contains the other and their UTF-16 length difference is at most 3, or when Levenshtein distance is at most `min(floor(0.3 * shorterLength), 2)`. Comparison is case-sensitive and uses the exact supplied strings. A candidate matching multiple known terms uses the first `knownTerms` entry; otherwise transitive candidate clusters choose the highest-count spelling, with first input order breaking ties. `research.terms.expand` keeps the trimmed literal first and appends only known terms passing that same rule in input order.

The sentence action uses the versioned `ja-sentence-v1` behavior: Japanese sentence-boundary segmentation, preserving punctuation and UTF-16 source ranges; do not split inside open `「...」` or `『...』` spans, and attach a closing quote to the sentence it closes. LF delimits lines without dropping source characters; an empty line yields an empty range. Token `sentenceIndex` refers to this exact ordered range list. The pinned source implementation is `modules/nlp/src/sentenceSplit.ts`; no focused unit test exists, so the acceptance fixture is normative for edge cases.

The historical nlp.features table includes permissions and tasks owned by Speaker, Paired Writing, Knowledge and Semantic. The current plugin cannot own those decisions. The legacy-consent read makes source data observable without duplicating another plugin's grant UI. The old nlp.updateExternalConsent guest action is retired: its user choice now opens the Host Plugin Manager permission review as a user gesture, and only that Host UI may create/revoke a local capability grant. Every external egress grant names the plugin, destination/scope, disclosed data, duration and user action.

### Shared errors and retries

All actions use the stable machine-readable code and user-facing recovery behavior in the [Host/Plugin Contract](../HOST-PLUGIN-CONTRACT.md). Common codes include invalid_input, unsupported_schema, repository_unavailable, missing_capability, plugin_unavailable, snapshot_stale, conflict, unapproved, capacity, cancelled, timeout and storage_unknown. Research feature errors below extend that taxonomy; implementations map equivalent conditions to these common codes rather than inventing parallel meanings. The WASM ABI also defines incompatible_abi and guest_trap. Never return ok:true with empty results when an index, registry or provider failed. A missing optional provider can return a successful lexical response with an explicit warning only when lexical results are complete for that same snapshot.

A cancelled action performs no authoritative mutation. If cancellation arrives after Host accepted a proposal, return its proposal receipt/state and let the author cancel or reject it in Host Review; do not pretend the proposal disappeared. Retrying a read is safe. Retrying proposals requires the same idempotency key. Stale input never auto-rebases or reapplies; refresh source and present a new review.

## 5. UI and author workflow

### Desktop

- Provide Research in the existing Host command/panel system, and include search in the Host's existing command palette shortcut (Ctrl/Cmd+K, from Loom's recovered workflow). Do not create eight permanent tabs. The Host supplies a dockable Search/Terms panel, keyboard focus management, result list, term forms, status and review links using validated descriptors.
- Search supports query, lexical/exact/prefix mode, path-scope chips, next-page controls and optional Morphology/Semantic switches. Lexical mode is initially selected. When Semantic is selected, the Host composes its separate public action into this one result surface. Search status identifies requested snapshot and index snapshot, indexed coverage, current/stale state, offline/provider warning and cancel/retry controls.
- Results show title, document path, bounded quote, exact source revision and score reason. Keyboard arrows move through results; Enter opens. A missing path or changed revision offers refresh/re-run instead of opening a stale offset. Result groups can show scene/volume/chapter labels only when Narrative resolves them; otherwise path stays visible.
- Terms view lists canonical spelling, aliases, target availability, alias collision and source revision. A synonym merge first reads the selected term with `research.synonyms.get`, then passes that exact revision-bound `groupRef` to the proposal. Add/edit/remove opens a Host-rendered form and then the Host ChangeSet review. A missing target cannot be followed. Candidate review displays count, reading, source evidence and actions to ignore/unignore or ask Knowledge to create an entity. Knowledge's `knowledge.entities.propose` action owns that proposal and its form.
- Editor decorations are non-editing, keyboard-accessible affordances with an accessible name and a navigation button. They cannot take editor focus during IME composition or remount CodeMirror. Selecting a decoration opens a small Host-owned preview; ambiguous terms list all candidate targets and do not auto-navigate.

### Mobile and return-to-writing behavior

- Search opens in a focused Host sheet/full-screen task with a thumb-reachable query, scope controls, results and cancel/back. It uses the same action and snapshot contract as desktop; paging and long result lists remain scrollable with no drag-only operation. Terms, candidate review, synonym entry and proposal preview use stacked accessible Host sheets with clear Save-to-review, Cancel and Return-to-writing paths; none requires drag, hover or landscape orientation.
- Opening a hit passes path plus revision and match range/sentence to Host navigation. Host flushes the current editor draft according to its normal dirty guard, remembers origin path, caret, selection, scroll, writing mode and focus, and restores them on Back/Return. If content changed while away, Host re-resolves the hit against the new revision and asks the author before using a stale range.
- A search/index/model result must not replace the current editor buffer or steal keyboard/IME focus. Search is cancelable during composition. Closing or suspending a sheet retains the query/result state only as local UI convenience, never as guaranteed draft durability.

### Observable states

Show not installed, disabled, enabled-idle, indexing, ready at snapshot, stale, partial/unavailable, canceling, and failed distinctly. The lexical search panel remains usable if tokenizer, Knowledge, Semantic, network, storage cache or plugin Worker is unavailable. Optional asset transfer shows publisher, digest, size and locality before download and can be cancelled; failure cannot block typing.

## 6. Change authority and revision rules

- **Read:** Search, index status/rebuild, list/get/expand/resolve, text analysis, token count, term candidate/variant discovery, synonym lookup and legacy-consent inspection. Derived cache writes are non-authoritative and quota-bound.
- **Proposal:** Term add/update/remove, synonym add/merge, candidate ignore/unignore. Each includes an expected snapshot and expected file revisions, complete read/write sets, stable operation IDs, evidence/path references and a deterministic before/after preview.
- **Host-only apply:** Host Review verifies repository, branch, snapshot, all expected revisions, path policy and operation idempotency; it applies only the user-approved subset. Host alone writes the worktree, journal, checkpoint, Git commit or remote branch. Rejected proposals leave Git data byte-identical. A current editor draft must never be rewritten by a term registration or candidate acceptance action.

If one registry file changes between proposal and review, return snapshot_stale, retain the original proposal for inspection, and require refresh/re-preview. A batch touching multiple files is atomic at the Host writer boundary or returns truthful per-operation receipts for a partial application; Research may not label a partial apply atomic.

## 8. Runtime, distribution and lifecycle

proprium.research is an independently versioned, signed WASM Component Model plugin under the common [WASM ABI](../../architecture/WASM-PLUGIN-ABI.md) and [Plugin Platform](../../architecture/PLUGIN-PLATFORM.md). Its manifest declares stable plugin identity/version, ABI compatibility, action schemas, UI contributions, capability requests, dependencies, asset digests/sizes, license/provenance and resource bounds. Host-rendered TypeScript supplies panel/list/search/form/status/review/navigation UI; the plugin supplies typed data and bounded actions. No publisher JS, guest HTML/CSS, raw DOM, IndexedDB, filesystem, Git, credential or arbitrary network imports.

Keep the query/indexer and term registry available as soon as the signed plugin is enabled. Instantiate the local morphology component only on a user-requested analyze/candidate/count operation. Do not fetch a dictionary/model merely because Search is opened. Verify publisher signature, artifact digest, ABI and every pinned dependency before activation. Store derived index data in Host cache, not meta/proprium/plugins/...; store author-authored registries/preferences only at the existing Git paths above via approved proposals.

Disable/uninstall cancels jobs, releases tokenizer and cache leases, removes derived cache for the plugin, and hides its decorations/panels. It does not delete or rewrite canonical files, drafts, accepted proposals, terms, synonym groups or ignore choices. A failed upgrade keeps a previously verified runnable version where compatible. The Host restores editor panel/focus state after trap, timeout, update, reload or mobile memory pressure.

## 9. Implementation order and plugin composition

Research is P1 after the first usable Narrative P0 loop. Deliver the model-free lexical search and path/scene jump first. Add term registry and decorations next, then bounded tokenizer/candidates/synonym review; Host UI may compose optional Semantic results last. The basic text/Markdown local export has a separate early P2 gate in Publishing; it does not depend on Research or a model. Narrative is optional for generic file results; Knowledge is optional for entity candidates; Semantic is optional for retrieval quality. The acyclic plugin DAG is Host → Research, Host → Narrative, Host → Knowledge, Host → Semantic. Research and Semantic share Host-defined revisioned passage/term read contracts; neither plugin imports or invokes the other. A single Host-rendered search surface composes results only after the user selects semantic/hybrid mode.

Internal NLP utilities remain grouped under Research because their workload, data inputs and author workflow are small, model-light and shared by search/terminology. Semantic remains separate because model assets, memory/device suitability, indexing cost, consent and independent disable/update have materially different lifecycle. Entity creation stays with Knowledge because it owns entity identity and schema. Do not split a standalone term/synonym or sentence-split plugin from Research.
