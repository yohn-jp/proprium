# Canon P1 — proprium.paired-writing

**Status: normative implementation target with recovery provenance.** Scriptorium source below proves recovered legacy behavior, not an active Proprium plugin. Proprium has not shipped this plugin. WIT, Host, and other plugin contracts define targets; they do not certify implementation.

## Role and partition

Paired Writing lets an author keep a scene open, inspect scoped context, optionally consult an external writing assistant, and review evidence-backed suggestions. It supports context, grounded Q&A, rewrite and continuation suggestions, summaries, dialogue topic/turn candidates, proposal preparation, and status/return flows. Context assembly, deterministic rewrite fallback and proposal review remain useful without a model, MCP client, network or Gateway.

The plugin owns context assembly, Context Manifest, bounded suggestions, ChangeSet v1 validation/translation, and paired-workflow contributions. It does not replace the editor, save/checkpoint/publish/export/share workspace content, own story hierarchy or canonical Knowledge, or approve its own suggestions. Host owns editor, files, snapshots, draft journal, proposal ledger, approval, apply, Git, publication, navigation and credentials. Narrative owns work hierarchy and scene structure. Knowledge owns entity/world/thread/event/sketch data. Diagnostics, Research, Speaker and Semantic own their analysis products. Calls to other plugins use the versioned Host registry with read or propose effects only. Navigation and provider egress are separate Host-mediated capabilities. One plugin groups context, suggestions and review because they share author intent and revision provenance. Speaker, Diagnostics, Research, Semantic and Knowledge remain separate because their data authority, dependencies, compute weight and independent disable/failure lifecycle differ.

The acyclic call graph is Host → Paired (hard); Paired → Narrative for scene identity and structural compilation (required only by the specific scene/structure operation); Paired → Knowledge, Research, Diagnostics, Speaker and Semantic only for the optional owning features listed above. Narrative and Knowledge compilers are read-only and never call Paired; Paired owns ordered dispatch and the one final generic proposal. Provider broker and MCP Gateway are optional Host capabilities, not plugin dependencies. Paired does not depend on Publishing. Disable of any optional owner removes only its feature-specific controls/results and leaves writing, local context and pending Host proposals usable.

Priority is P1 after the functional H0 Host and Narrative P0 loop. First ship snapshot-bound Context/Manifest, deterministic rewrite fallback, exact selection proposals and offline return-to-editor behavior; then enable optional summaries, QA and paired external generation with consent and owner proposals. Paired never gates scene open, plain editing/local save/recovery or the early UTF-8/EPUB portability slice. Completing Paired alone, or P0 alone, is not full product recovery.

## Scope and data contract

Every call uses the Host contract Scope, Snapshot, ActionRequest, ActionResult, FileRevision and SourceSpan types; this canon does not create parallel envelopes. Bind actual repository identity, branch, Host snapshot, workspace generation and exact target identities/revisions. Scene context includes work ID if known, scene ID/path, manuscript path, scene revision and manuscript revision from Narrative/Host. repository_id is not legacy Scriptorium projectId. Read results include snapshot and every source revision. A live draft has a separate ephemeral revision and explicit base snapshot/scene revision; it is never called saved, committed or published.

Paired-specific WritingContextSnapshot is {scope,snapshot,target,parts,draft}. Target contains work/scene identity, scene metadata path+revision and the explicit manuscript path+revision. Each part contains stable part ID, source kind, source identity/path, revision/hash or null when not applicable, source/included character and byte counts, token count/status (provided, approximate or not_measured), inclusion reason, truncation/freshness, consent state, and origin (saved, explicitly shared selection, explicitly shared draft or client-provided selection). ContextManifest is {scope,snapshot,external_host_final_prompt_observed:false,draft:{status:not_shared|explicitly_shared,revision?},parts}. Token count never implies a model tokenizer unless provider/model identity is returned.

Canonical YAML/Markdown and the existing workspace settings JSON use round-trip representation preserving comments, ordering, unknown keys, aliases and line endings. If preservation cannot be established, fail with `unsupported_format` and leave original bytes untouched. Unknown ChangeSet fields are rejected by the versioned validator and kept in recoverable source payload; never silently strip them or serialize a reduced DTO over source files.

Host-local `plugin.preferences` are the current user's interactive defaults and take precedence over workspace-authored defaults for that user. `paired.workspace-settings.read` reports both values, effective preset/model aliases and provenance without conflating scopes. The explicit `paired.workspace-settings.propose` path stores only nonsecret, shareable model/preset choices in the existing Git settings file and requires an explicit UI gesture plus ordinary Host review/apply. A Git setting is never a provider, endpoint, credential, model download, egress grant or consent record. Provider allowlisting, secret resolution and per-request disclosure remain Host-owned. Legacy importer and current schema fields retain unknown JSON keys; malformed source is preserved and blocks overwrite until explicit recovery.

### Dialogue-sketch assets

`bible/dialogue_sketches/<id>.yaml` is Knowledge-owned author data. Paired only reads a sketch through `proprium.knowledge` actions and supplies topic/turn candidates; it does not create, edit, save or delete sketch records. Participant entity IDs, ordered speaker lines, unknown YAML keys, revisions and save/review UI are defined by [Knowledge](KNOWLEDGE.md#dialogue-sketch-assets). Without Knowledge, manual topic/turn inputs remain usable but saved-sketch lookup and profile enrichment report `dependency_unavailable`. The Loom editor is recovered UX for Knowledge, not a second Paired data owner.

Never turn unknown-data loss, partial apply, missing evidence or provider uncertainty into success.

### NarrativeChangeSet v1 intake and generic proposal compilation

The compatibility intake preserves source envelope `{schemaVersion:1,id,projectId,goal,status:"proposed",assessment:{confidence:0..1,risk:"low"|"medium"|"high"},operations:[1..64],evidence:[0..256],diagnostics:{before:{id,revision}|null,after:{id,revision}|null}}` with a strict v1 adapter and actual Host workspace binding. IDs, project IDs, source IDs and revisions are nonempty strings of at most 256 characters; `goal` is 1–10,000 characters. Verify any legacy project-to-repository association; never equate `projectId` to `repository_id`. Every operation has exact keys, a unique stable `id`, `kind`, `evidenceIds:[string<=256][0..64]`, assessment, exact target and a revision/content-hash precondition (or `absent` only for creates). Existing-source precondition is exactly `{kind:"revision"|"content-hash",value:string<=256}`; absent is `{kind:"absent"}`. Evidence is exactly `{id:string<=256,sourceKind:"manuscript"|"entity"|"scene"|"diagnostic"|"state-proposal"|"external",sourceId:string<=256,revision:string<=256,range?:{start:integer>=0,end:integer>=start}}`. Each range is UTF-16 and checked against the exact ActionRequest snapshot. Every key is strict; duplicate evidence IDs, operation IDs, or operation targets fail. Source JSON is limited to depth 16, 10,000 nodes, 1,000 elements/keys per collection, 100,000 characters per string, and 1,000,000 serialized characters overall; unsafe prototype keys fail. Preserve the complete accepted source payload/fingerprint and diagnostics in immutable proposal evidence so the original input is inspectable and never round-tripped through a lossy DTO.

The proposal intake is Paired-owned because it recovers Scriptorium `story.changes.propose`. It does not make Paired the semantic owner of Knowledge or Narrative files. It calls these public pure compiler actions through the Host registry; they declare `read`, never submit their own proposal, and have no callbacks to Paired:

Compiler input is `{operations:SourceV1Operation[1..64],evidence:SourceV1Evidence[0..256],staging_snapshot?:string}` within the shared request's original scope/snapshot. Paired batches only operations of the same owner that preserve source order, and stages between batches. The optional opaque stage is Host-issued. Each compiler reuses its public propose action's validator and patch generator, but never submits a proposal or receives write authority. Validation failure fails the whole compiler call; diagnostics never conceal rejected operations. Source IDs resolve only through the verified workspace binding, never legacy server authority.

Paired validates all source operations first, then invokes the owner compiler in original source order. After each batch, Host `workspace.change.stage({base_snapshot,previous_stage?,units})` checks preconditions and overlays exact generated bytes in ephemeral quota-bound storage, returning `{staging_snapshot}`. A stage is read-only, bound to the caller chain/workspace/original snapshot, and cannot alter worktree, editor, draft journal or Git; it is released on cancellation and cannot cross reload/workspace. Later compilers receive this stage and may read it only within orchestration. They validate later operations against the virtual view, while final preconditions/read revisions refer to the original request snapshot, including null for original absence. `manuscript.replace-range` is compiled by Paired against the explicit manuscript path and exact UTF-16 span. Missing/disabled owner returns `dependency_unavailable`; Paired does not reinterpret or drop an operation.

Paired collapses repeated staged writes to the same path into one original-base-to-final-bytes operation; a later edit depends on the earlier source operation and never treats staged bytes as a saved revision. Overlapping paths, created-ID references and declared dependencies join one inseparable dependency-closed unit; independent components remain separately selectable units in source order. A `scene.update` spanning structural and semantic scene fields is compiled by both owners with one source operation ID and one inseparable unit. Cyclic dependencies fail `invalid_input`; forward references unavailable in source order fail with the source operation ID. Incompatible same-path changes fail `conflict`. The final proposal is one Host `workspace.change.propose` call with `{id,idempotency_key,scope,snapshot,title,reason,read_set,units,evidence}`. A unit is `{id,label,depends_on,operations}`; each generic operation is `{id,kind:create|replace|delete,path,expected_revision,content?:byte[],content_artifact?:string}`; create uses original `null` revision, replace/delete use original SHA-256. No unit writes the same path twice. All source evidence spans and resulting paths/revisions map to source operation IDs. Host receives only generic path operations and exact bytes/artifacts; it never parses scene, Bible, timeline or thread YAML. Host applies reviewed units at original revisions only, reports actual per-unit receipts/partial outcomes, and never publishes.

## Errors, cancellation and idempotence

Every failure returns shared `ActionResult` with `request_id`, scope, snapshot and the Host error envelope. This plugin uses common required codes `invalid_input`, `unsupported_schema`, `repository_unavailable`, `scene_not_found`, `missing_capability`, `plugin_unavailable`, `snapshot_stale`, `conflict`, `unapproved`, `capacity`, `cancelled`, `timeout`, `storage_unknown` and `publication_unknown`, plus Host extensions `capability_denied`, `invalid_path`, `invalid_encoding`, `file_not_found`, `unsupported_format`, `ambiguous_identity`, `dirty_draft`, `dependency_unavailable`, `provider_unavailable`, `external_state_unknown`, `artifact_too_large`, `idempotency_conflict`, `incompatible_abi`, `guest_trap` and `repository_not_active`. A missing local source maps to `scene_not_found` or `file_not_found`; denied per-request provider consent maps to `capability_denied`; oversized context uses `capacity` or `artifact_too_large`; unsupported legacy operation/schema uses `unsupported_schema`. There is no successful-empty result for missing capability, source, evidence or coverage.

Reads replay only against their original pinned snapshot. Deterministic compute is reused only for identical input/provider/prompt/plugin version/source revisions. Unknown provider completion is not restarted automatically. Proposal keys are workspace+plugin+action+idempotency key+canonical request digest; exact retry returns existing proposal/receipt, changed payload fails `idempotency_conflict`. Host apply is operation-ID idempotent and rechecks every revision immediately before applying. Stale output never appears current. Cancel before submission makes no proposal; after submission preserves it. Cancel is never rejection/deletion. `partially_applied` is a truthful result status with per-unit receipts, not a success code or rollback promise.

## Acceptance — observable completion

Every ledger row maps to an acceptance below. Build and inherited tests alone do not satisfy these conditions.

<a id="pw-01-provider-free-and-optional-provider"></a>
### PW-01 — Provider-free and optional provider

With all providers unset, cold Host opens Context, runs local rewrite fallback/context, reads status, inspects proposals and can use external MCP path. Activation allocates no Worker/network/model/credential lookup. Enabled provider shows alias/model/exact disclosure per request. Cancellation/error is truthful, unknown completion is not retried. Malicious manifest cannot read/return Host secrets. Host-local preference changes happen only in Host controls; `paired.workspace-settings.propose` saves explicit nonsecret Git defaults through review/apply and never grants consent. The legacy `assistant.settings.propose` ID is not a guest preference mutation; its UI adapter uses this explicit workspace-authorship flow and non-UI mutation callers receive `capability_denied`. An absent broker returns `provider_unavailable` without blocking local work.

<a id="pw-02-rewrite-and-selection"></a>
### PW-02 — Rewrite and selection

Select exact UTF-16 range in Japanese scene. See three strategies/rationales/citations; split/tell-show appear when conditions match. Choosing one displays exact diff and submits only range proposal. Duplicate ambiguous text, stale range/revision, changed draft, same replacement, invalid offset, provider timeout or cancel never edits. Provider absent/failure still returns local candidates. Host apply changes selected range only and returns to same scene/anchor.

<a id="pw-03-continuation"></a>
### PW-03 — Continuation

For scene with over 8 sentences, preview exactly context used; default latest eight. Check k=0, budget boundary, optional current summary, five ranked retrieval hits, missing/approximate counter labels. Shared draft requires exact scene/path/base snapshot/base scene revision and is marked unsaved. Wrong repository/branch/scene or stale base fails. Preview needs no model.

<a id="pw-04-qa-and-manifest"></a>
### PW-04 — QA and Manifest

Ask multi-turn question about two scenes/Bible entity. Search is bounded/scoped; quote matches current path/revision. No evidence gives uncertainty/empty citations. Manifest lists included/omitted part, source, revision, counts, truncation and consent. Draft is absent by default; client selection is explicit and distinct. Never claim to know hidden model prompt.

<a id="pw-05-summary-and-first-read"></a>
### PW-05 — Summary and first read

Scene summary has ordered lines, known characters, revisions, hash and provenance. Repeat matching input is cached; manuscript change makes stale. Chapter with up to 30 scenes proposes child+parent; empty or over-30 fails typed. First read uses only accepted current ordered summaries through target chapter and cites revisions. Nothing mutates before approval.

<a id="pw-06-dialogue-sketch-workflow"></a>
### PW-06 — Dialogue Sketch

Create/list/reopen/edit/save standalone sketch with title/situation/participants/ordered speaker lines; unknown keys survive. Invalid participant or stale base cannot overwrite. Topics return 3–5 title/situation pairs, use manual relations/links, exclude auto links. Turns return one selected speaker or exactly 1–30 lines by selected participants; stale sketch, invalid speaker, empty/malformed output fails. Without Speaker, YAML voice notes still work. Optional Knowledge analysis is pending review, never auto-updates Bible.

<a id="pw-07-delegated-features"></a>
### PW-07 — Delegated features

Independently disable Knowledge/Research/Diagnostics/Speaker/Semantic. Action registry reports each feature's owner and unavailability reason; Paired core/context/edit actions continue. Diagnostics is the sole deterministic aspect-review owner. Paired retains optional-provider synonym, Zukan and state-event generation; term adoption, entity corrections, event proposals and sketch CRUD use Research/Knowledge owner proposals only. With Knowledge absent, saved-sketch/Zukan/state reads and adoption return `dependency_unavailable`; manual dialogue inputs still work. With Research absent, synonym candidates can be generated but cannot be adopted into Research records. With Semantic absent, candidate-ID contradiction review returns `dependency_unavailable`; free-text contradiction and Zukan grounding use bounded lexical fallback and mark reduced coverage. With Speaker absent, voice notes remain available and no attribution is fabricated. Disabling the provider cancels its own jobs; editor and pending Host proposals survive. UI/MCP invoke the same typed owner action contracts.

<a id="pw-08-desktop-mobile-and-ime"></a>
### PW-08 — Desktop/mobile/IME

Desktop switch Context/Inspect/Changes during Japanese IME; preserve text/selection/undo/scroll, review full diff in Host, return focus to same editor. Mobile Safari/Chromium: open sheet, use touch/keyboard, rotate, show/hide virtual keyboard, close/reopen review and return to same scene/anchor. Suspension/reload reveals actual journal state and never reports remote save. Invalid old anchor goes to nearby recovery location, never guessed caret.

<a id="pw-09-runtime-privacy-and-failures"></a>
### PW-09 — Runtime/privacy/failures

Reject bad ABI/signature/digest, incompatible dependency, undeclared capability or malformed UI. Disabled allocates no Worker; idle unloaded; demand starts bounded worker; cancel releases it. Test quota/timeout, malformed/oversized RPC, trap, missing cache, offline, corrupt cache and unsupported device. Host editor remains available/files unchanged. No egress absent per-request consent. No network/secret/DOM/Git/filesystem imports. Offline requires verified cached bytes.

<a id="pw-10-mcp-retry-and-staleness"></a>
### PW-10 — MCP retry/staleness

Connected MCP reads saved context/Manifest, submits two ops with evidence and retrieves status/diff. Cross-repo ID, legacy project mapping mismatch, unsupported op, unsafe path, stale base, missing quote, duplicate op, same key/different fingerprint or oversize produce typed errors. Exact retry returns receipt. Editor change after proposal yields stale and retains draft. Approve one operation, leave other untouched. After disconnect query status before retry; unknown not success. MCP cannot approve/apply/commit/publish. Approved apply returns exact revisions/receipts and returns editor to scene.

<a id="pw-11-recovery-and-completeness"></a>
### PW-11 — Recovery/completeness

For archived settings/usage with unknown fields, missing/matching/conflicting target, preserve bytes; restore exact source only by explicit recovery approval; surface conflict without selecting version. Usage DTO bounded/hides unknown fields; JSONL unchanged. Old `.arcadia` path is not a writable canonical target. Every ledger row maps to action/UI/data owner and acceptance. Host-local nonsecret preferences change only from Host controls on a user gesture; legacy `assistant.settings.propose` never mutates Host-local preferences and non-UI callers cannot invoke it. Its explicit UI equivalent is `paired.workspace-settings.propose`, a separate reviewed generic ChangeSet that preserves unknown JSON fields and grants no egress. Gaps remain RECOVERY_PENDING, not deleted or claimed complete.

<a id="pw-21-mixed-changeset-compilation"></a>
### PW-21 — Mixed ChangeSet compilation

Submit source v1 sets exercising each of the nine accepted operation kinds, an identity-bound `projectId`, exact evidence, and a set that creates then references a staged entity. Narrative and Knowledge compilers run in source order against Host staging; the output has one complete original-base `read_set`, all source operation IDs map to generic file operations, and a same-path cross-owner edit becomes one dependency-closed review unit with the final byte diff. No worktree, editor draft, owner proposal or Git byte changes before Host review/apply. A mixed semantic/structural `scene.update` receives validation from both owners and remains inseparable. A missing compiler returns `dependency_unavailable` without dropping the source payload or creating a partial proposal; an unsupported kind, `thread.link-scene:advanced`, forward reference, duplicate ID/target, ungrounded quote, unsafe path, conflicting write or cyclic dependency returns a typed error tied to its source op. A stale original revision or dirty manuscript at review blocks apply and retains the proposal/draft. Same idempotency key+source fingerprint returns the same Host proposal; changed source bytes return `idempotency_conflict`. Disable Paired after submission and verify the Host proposal/evidence remains reviewable; owner plugin disable never creates a second partial ChangeSet.

Certification uses a signed plugin artifact in Chromium/WebKit including mobile classes, real Host editor/navigation and persisted/reloaded public-domain/generated workspace. Legacy Scriptorium/Loom checks prove source behavior only; they do not certify Proprium Browser Git, mobile, WASM, Gateway or static delivery.
