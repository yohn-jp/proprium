# P2 Canon — `proprium.speaker`

**Product job.** Give an author a reviewable account of who speaks each line, a quick way to correct uncertain attribution, character-by-character dialogue and voice views, and evidence about how well the attribution rules work. Every result is a hypothesis tied to the source revision; only an author-confirmed override is a fact. This plugin is an optional P2 tool and never gates writing, scene navigation, save, recovery, or local Git.

**Status.** This document specifies the Proprium recovery target. Scriptorium's TypeScript implementation is source evidence, not a Proprium plugin implementation. The WIT component, broker, Host-rendered UI and real-browser proof remain to be built.

## Boundary and partition

Speaker owns dialogue segmentation, speaker attribution and grouping, speaker-count estimates, author corrections, voice evidence, and attribution evaluation/training. Narrative owns work/scene identity and manuscript navigation; Knowledge owns character identities and their declared voice profiles; Research may provide Japanese tokenization; Diagnostics may provide generic voice/style measures. These are calls to public typed actions or capabilities at the same pinned snapshot. Speaker never imports another plugin's internal code, writes a character record directly, or owns a second story graph.

Keep Speaker independent because its correction feedback, corpus scans, evaluation jobs and optional reranker have a distinct lifecycle and can be disabled without disabling writing. Do not split attribution, correction review, dialogue listing, voice evidence, evaluation and training into tiny plugins: they share the same source lines, character IDs, confidence policy and feedback data. Do not merge Speaker into Diagnostics: Diagnostics can consume Speaker attribution while Speaker optionally consumes generic style measurements, so integration is one-way through public contracts and the style provider is optional. The existing Scriptorium module required Story/NLP/Diagnostics at runtime; Proprium fixes that coupling as specified under [Dependencies](#dependencies-and-degradation).

Speaker MUST NOT own manuscript editing, prose rewriting, automatic correction, Git, checkpoint, publish, editor DOM, global keyboard handling, persistent browser storage, remote model credentials, arbitrary network egress, or unreviewed metadata writes. No external model, server, Gateway or account is required.

## Data contract

All reads are revision-pinned to `{repository_id, branch, workspace_generation, snapshot}`. For every scene row the snapshot includes the explicit scene YAML path/revision, the linked manuscript path/revision (or active draft generation/hash), candidate character record revisions, and the optional model/tokenizer/diagnostics identities used. Never infer a Markdown path from a scene ID. The same scene ID in another repository or branch is a different input.

| Data | Authority, shape and write rule |
| --- | --- |
| Scene metadata | Existing `plot/volumes/<volume>/chapters/<chapter>/scenes/<scene>.yaml`, located through Narrative's explicit scene record. Existing `speakerCount` is an optional positive integer. New estimate is derived; only an author-approved update changes `speakerCount`. |
| Manual attribution | Existing scene YAML `speakerOverrides[]` is the current truth. Preserve the existing shape: `{sentenceIndex?, textHash?, dialogueText, speakerEntityId: string|null, speakerGroupId?, source?: "direct"|"propagated"}`. `null` means author-confirmed unknown/unnamed, not missing data. `direct` is protected from propagation; absent legacy `source` is treated as `direct`. New entries set a one-based sentence index and the legacy-compatible lowercase eight-hex FNV-1a 32-bit hash of `dialogueText.trim()` over UTF-16 code units. A sentence/hash match is required; a unique hash can re-anchor after line insertion, while zero or multiple matches are stale and remain visible for repair. |
| Correction history | Existing legacy `meta/scriptorium/modules/speaker/corrections.jsonl` is retained byte-for-byte and read-only until an explicit migration is approved. Every new confirmed correction appends one event per changed line at `meta/proprium/plugins/proprium.speaker/corrections.jsonl` through the same Host-reviewed ChangeSet as the scene YAML update. This file is an append-only audit/training event stream, not the current override authority. Each v1 event has `sentenceIndex`, `textHash`, `dialogueText`, `predictedSpeakerEntityId`, `predictedReason`, `speakerGroupId`, `label`, `sceneId`, `speakerEntityId`, and timestamp. Preserve existing lines, malformed lines, unknown JSON keys and line endings; never normalize/rewrite the whole log. Gold labels and current output always come from scene `speakerOverrides`. |
| Adopted model | Optional, versioned local reranker configuration at `meta/proprium/plugins/proprium.speaker/adopted-model.json`, written only by reviewed proposal. V1 fields: `version: 1`, ordered unique `featureNames`, finite numeric `weights` with one value per feature, finite `bias`, `highProbabilityThreshold` in `[0,1]`, ISO-8601 `trainedAt`, `holdoutSceneIds`, and optional `metrics` (`trainAccuracy`, `holdoutAccuracyWithoutModel`, `holdoutAccuracyWithModel`, `adopted`). V1 feature names follow the fixed ordered set in `speakerReranker.ts`; an unknown version or incompatible feature vector means “model unavailable”. Same-version unknown fields must be preserved across review/apply. The historical `meta/scriptorium/modules/speaker/adopted-model.json` is retained read-only and is never silently copied, upgraded or overwritten. |
| Declared character voice | Existing Knowledge-owned `bible/characters/<character>/profile.yaml` (or the validated existing identity record) field `voice_profiles[]`; each profile has stable `id`, optional `context_trigger` (`match_metadata` with key/value or `text_structure: monologue`), optional `firstPerson[]`, optional `sentenceEndings[]`. Unknown keys/fields and unrecognized triggers remain untouched and are reported as unsupported data, never stripped. Speaker reads; Knowledge owns changes. |
| Derived results | Attribution, scene clusters, voice fingerprints, matrix, profile statistics, diagnostics, rule gates and evaluation output are derived from source snapshot plus algorithm/model/provider/config identity. Keep them in a quota-bound plugin cache keyed by repository, branch, snapshot/overlay or draft generation, scene corpus definition, character revisions, algorithm version and each provider/model digest. Never commit cache output or treat it as author state. |

A correction proposal has two ordered writes: the scene YAML override and one appended audit event for every selected line. Both file reads include exact revisions and every manuscript line includes the source revision/hash that supplied it. The Host applies the approved operation atomically or returns a truthful recoverable partial receipt; it never reports atomic success for partial application. The proposal shows the YAML semantic diff and each log event separately. YAML editing preserves all unknown mappings and existing author values; if comments/formatting cannot be preserved, the diff is shown for review. No generic whole-file serializer may erase unrecognized fields.

Speaker's only source-of-truth updates are these reviewed metadata changes. It cannot write an editor draft, change its own cache into tracked data, or publish a Git ref.

## Typed action contract

The stable v1 Action IDs below use only Host effects `read` and `propose`. `read` includes bounded local computation and may allocate a temporary Worker; it has no persistent effects. Every request carries the Host envelope `(scope, snapshot, request_id, action_id, input)` from the shared Host contract. Every response echoes scope/snapshot and lists source revisions plus algorithm/provider identities. Unrecognized fields are rejected for action inputs; stored user data is open-world and preserved as defined above.

All actions require a live enabled plugin instance and current Host snapshot. Host cancellation or deadline stops the job; a terminated Worker releases its capability leases, returns no partial result as current, and writes no cache entry after cancellation. For `read`, identical input + snapshot + provider identity is observationally idempotent. For `propose`, `idempotency_key` is mandatory: same key and canonical input returns the same proposal; reusing it with different content is `idempotency_conflict`. Proposal application still requires Host review and compare-and-swap of every read/write revision.

| `speaker.retraining.run` / `propose` | `{holdout_scene_ids?,dry_run?:false,idempotency_key}` → `{train_example_count,holdout_scene_ids,accuracy_without_model,accuracy_with_model,delta_percentage_points,high_probability_threshold,adopted,model_candidate?,adoption_proposal?,provenance}`. Default holdout is the deterministic 20% scene subset (at least one, leaving at least one training scene); caller-specified IDs must be gold-labeled scenes. | At least 10 training examples and one matched held-out label are required. A candidate is eligible only if held-out attribution accuracy improves by at least 5 percentage points. High threshold targets 95% precision with at least five observations; fallback is 0.90. Adoption is a Host proposal to the Proprium model path, never a write. `dry_run:true` returns metrics without proposal. Errors: `invalid_input`, `empty_holdout`, `insufficient_training_examples`, `no_matched_holdout`, `cancelled`, `timeout`, `snapshot_stale`, `idempotency_conflict`. Existing adopted model remains active until approval and revision check. |

The WIT schema must encode nullable unknown speaker separately from omitted/invalid input, bounded strings/arrays, one-based sentence index, UTF-16 offsets, confidence/reason enums with forward-compatible unknown-reason display, provenance and snapshot references. Current common Host protocol permits `read`, `propose` and Host-only `apply`; do not introduce legacy `compute` as a third mutation effect.

### Attribution policy

Each returned dialogue must retain the exact source substring and line identity, with one-based sentence index for compatibility and UTF-16 span for navigation. Supported reasons include `attribution-verb`, `attribution-verb-subject`, `strong-hint`, `pov-reply`, `preceding-narration`, `vocative-other`, `addressed-by-next`, `alternating-turn`, `rerank`, `manual-override`, `mob` and `none`. An unknown future reason is displayed as an unknown rule code and never interpreted as a fact.

Automatic `high` is allowed only for an empirically calibrated rule meeting the declared high-precision policy. Current recovered source allows `preceding-narration`; candidate proximity and weak hints remain `low`. A reranker may emit `high` only at its held-out calibrated threshold. Manual author confirmation is displayed as confirmed and carries `manual-override`; an unresolved group remains `speaker_entity_id:null` with a separate `speaker_group_id`. “Unknown speaker” is a valid author decision. A mob is never auto-assigned as a character.

## UI and author workflow

Use the existing Host desktop/mobile shell, editor, panels, modal/sheet, review queue and status components. Speaker registers stable declarative surfaces; Host renders them. The panel switch must not remount the editor or reset its undo stack, reading position, selection, IME composition or draft journal. Contributions are `speaker.attribution`, `speaker.review`, `speaker.dialogue`, `speaker.voice.profiles`, and `speaker.evaluation`; these are surfaces in the existing workspace, not new top-level application shells.

On desktop, the attribution panel selects a scene, runs analysis on the current document, then displays every dialogue line with speaker/group, confidence badge, reason explanation and source evidence. Selecting a row asks Host Navigation to jump to its sentence. The side review panel lists `none` before `low`, shows scene and group propagation count, and lets an author choose a Knowledge character or “unknown / unnamed.” A propagation preview identifies every line before the author includes any group members. A correction button creates a ChangeSet; its status says pending review, approved/applied, stale or rejected. It never says saved before Host reports apply success.

The character view selects a Knowledge character and optional scene/confidence filter, then shows cited dialogue excerpts and a voice profile/matrix with sample counts, comparison method and source revisions. The voice check can analyze either the persisted scene or an explicit current draft generation and groups warnings by declared rule, learned fingerprint or stylometric evidence. Every issue has a sentence jump. None of these results rewrites the manuscript.

The evaluation view has separate controls for “evaluate”, “update gates”, “retrain”, and “dry run”. It displays model/algorithm/provider identities, corpus and gold sample counts, all metrics, per-rule denominators/precision/gate, hash-mismatch exclusions and expandable scene/line evidence. Model adoption is visible as a distinct Host proposal with held-out improvement; failure or rejection leaves the previous model intact. There is no hidden “auto learn” from the author's unreviewed draft.

On mobile, expose the same actions in a thumb-reachable scene sheet, scrollable review list and full-width report/detail sheet. Buttons have text labels and keyboard/touch alternatives; no drag-only interaction. Returning from an evidence row or review proposal returns to the same scene and sentence in the same editor. When the virtual keyboard is open, opening/closing a sheet does not replace composition text or unexpectedly focus a picker. Back/cancel closes the panel and preserves current input. If the source changes while review is open, keep the selection locally, show it as stale and offer refresh; do not submit against a new source implicitly.

## Changes and Host authority

Scene scan, attribution, queue, voice profile/check, dialogue list, evaluation and training metrics are reads/derived computations. The Host owns navigation and any save action. Only `speaker.override`, `speaker.count.update`, optional correction-history append, and eligible model adoption create proposals. Every ChangeSet carries repository/branch/snapshot, ordered operation IDs, exact scene/character/manuscript/log/model read sets, expected revisions, write sets, text hashes and an author-readable preview. Host validates capability, target path, dirty-buffer state, idempotency key and every revision before Apply.

A pending proposal must not overwrite keystrokes made after it was created. If the editor has an unsaved draft, the Host returns `dirty_draft` and asks the author to save/resolve the draft before applying against a fresh reviewed base; it never refreshes the editor from proposal output. A newer revision produces `snapshot_stale` and a refreshed preview. Reject is a no-op on Git. Apply is not commit or publication. MCP may invoke the same read/propose action through Host dispatch, but an MCP caller cannot approve/apply it.

## Execution and distribution

`proprium.speaker` has a stable publisher-scoped identity, signed immutable artifact, digest-pinned version, declared WIT/Host ABI range, permissions and provider capabilities. Host verifies publisher trust, signature, digest, schema and dependencies before instantiation. The compute pipeline, segmentation, attribution rules, clustering, profiles, evaluation and reranker are WASM Component Model code in a terminable Worker. Existing trusted editor/shell widgets remain Host TypeScript; plugin UI is a validated declaration rendered by those components. No arbitrary plugin JavaScript, DOM, filesystem, IndexedDB, Git credential or direct network import.

Installation and enablement do not allocate a Worker or download model data. Activation is lazy on author demand. The tokenizer/provider lease and Speaker Worker are bounded to an action and released on completion/cancel/disable; batch corpus work yields progress and honors backpressure. Apply repository-derived CPU, byte and duration bounds, starting with the recovered 500-scene, 500,000-character/scene, 10,000-review-row, 500-dialogue/20,000-character profile corpus and 120-second job limits; exceedance returns a specific error with no partial current result. Tests must set safe mobile budgets before claiming physical-device support. Low memory or missing threading never blocks the editor.

Assets such as tokenizer dictionaries or a reranker are separate immutable, digest-verified non-executable data assets with publisher/license provenance and explicit size/consent. The bundled deterministic fallback has no downloaded model dependency. No model weights from third parties, credentials, private manuscripts, or Loom/Scriptorium test fixtures are copied into the plugin artifact. Disable/uninstall cancels jobs, releases leases and hides stale results; it never deletes source YAML or correction history.

### Suite and no-loss gate

Before the eight-plugin suite is declared recovered, every SPK feature above must pass on the signed artifact installed in a production-like Host with no server. Stale proposal, branch switch, offline cached use, missing source file, missing character, malformed YAML/JSONL, worker trap/timeout/cancel, cache corruption, quota exhaustion and mobile tab suspension must leave author bytes intact and expose truthful status. Narrative remains the only scene hierarchy owner; Knowledge remains the only character/voice definition owner; Speaker owns no author prose. See [suite acceptance](../ACCEPTANCE.md) for release-wide certification.


The action table's plugin payload is wrapped in the exact H0 v2 `ActionRequest`/`ActionResult`. Draft input is valid only when Host issued the matching `draft_generation`; the guest cannot manufacture it. Legacy domain errors such as `scene_too_large`, `corpus_too_large`, `review_queue_too_large` and `voice_corpus_too_large` map to `capacity` with `details.legacy_code`; `cursor_stale` maps to `snapshot_stale`, `invalid_scene_path` to `invalid_path`, and `proposal_rejected` to `unapproved`. `no_gold_data`, `empty_holdout`, `insufficient_training_examples` and `no_matched_holdout` are typed validation reasons under `invalid_input`. `ambiguous_reanchor` maps to `ambiguous_identity`. The shared H0 limits take precedence over historical source caps: page results before the 1 MiB envelope ceiling and use sealed artifacts for larger model/report bytes.
