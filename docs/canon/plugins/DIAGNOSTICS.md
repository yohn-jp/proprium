# P1 — `proprium.diagnostics` (Writing Diagnostics and Continuity)

**Status: normative recovery and implementation target.** This specification records behavior recovered from Scriptorium and Loom and the additional Host-facing contracts required by Proprium. It does not claim that an installable Proprium Diagnostics artifact or its full UI already exists. `proprium.diagnostics` is independently signed, versioned and disableable. Its compute is local and model-independent at baseline.

## Product role and limits

Diagnostics helps an author inspect a scene or work, understand evidence behind a finding, and decide whether to change anything. It covers structural consistency, declared continuity, manuscript format, prose measurements, lexical/style signals and clearly labeled interpretive hypotheses. Every result is read-only. Any persistent correction, acknowledgement or text change is a Host-reviewed proposal.

The plugin does not own the editor, Draft journal, scene hierarchy, canonical entities, speaker corrections, search index, Git writer, publication or model service. Narrative supplies work/scene/path identity; Knowledge owns canonical entity and world-state facts; Research owns terminology and lexical search; Speaker owns attribution, correction and voice-profile source records; Semantic may supply optional model-based candidates. Diagnostics consumes their typed read results at the same Host snapshot and owns finding normalization, provenance and presentation. It never depends on their private files or implementation.

A deterministic error means a reproducible violation of a declared file, link or rule contract. A statistical signal is only a pattern worth inspecting. A semantic or first-read result is a hypothesis. Missing facts, an unknown character state, or a weak similarity score are not contradictions. No score may override the class and severity of a verified structural error.

**Priority:** P1, after H0 and Narrative P0. It is required for a practical long-form writing environment; a working P0 authoring loop alone does not establish full product recovery. A basic plain-text/EPUB export is separately prioritized by Publishing for data portability and does not depend on Diagnostics.

## Canonical data and revision contract

Diagnostics reads Git files only through the Host's revision-pinned, paged snapshot interface. For a narrative repository, the scene's declared `manuscript` path is authoritative. The plugin must not infer a path from an ID or require `bible/`, `plot/` or `manuscript/` in generic repositories. Project checks report “not a recognized narrative work” / no findings when the source layout is absent; they do not create or normalize it.

| Data | Canonical source / owner | Diagnostics treatment |
| --- | --- | --- |
| YAML entities, scene goal/conflict/intended tone, thread links, locations, event/effect and ordering fields | Existing Git YAML; Narrative/Knowledge define interpretation | Read at one snapshot. Unknown keys are opaque. Preserve original document bytes on every operation except an explicitly reviewed targeted operation. |
| Manuscript Markdown, frontmatter, author markup and ruby/Aozora notation | Existing Git Markdown; Host editor owns active Draft | Read exact saved revision or receive an ephemeral Host Draft overlay tagged with document path, revision and generation. No returned finding may replace text. Keep frontmatter untouched in formatter proposals. |
| Existing lint/tone/plot config | `meta/scriptorium/modules/diagnostics/lint-rules.yaml`, `tone-lexicon.yaml`, `plot-lexicon.yaml`; legacy migration may also find `meta/lint-rules.yaml`, `meta/tone-lexicon.yaml`, `meta/plot-lexicon.yaml` | RECOVERY paths. Parse supported keys, retain unknown YAML keys and comments. Missing file uses documented built-in defaults. A malformed file is a visible configuration error; do not silently replace it with defaults or rewrite it. |
| Synonym groups | `meta/scriptorium/modules/nlp/synonyms.yaml`, owned by Research/NLP | Read-only to Diagnostics. Keep unknown fields; registering/merging a term is a Research proposal against file revision. |
| Speaker corrections, speaker settings and Knowledge feedback | Speaker/Knowledge-owned existing YAML/JSONL paths | Read only via typed action result. Diagnostics neither migrates nor writes them. |
| Historical Semantic contradiction dismissals | `meta/scriptorium/modules/semantic/contradiction-dismissals.jsonl`; source/import path may be `meta/contradiction-dismissals.jsonl` or preserved under `meta/scriptorium/modules/semantic/legacy/files/meta/contradiction-dismissals.jsonl` | RECOVERY data owned by the old Semantic action. Diagnostics is the new owner: an explicit Host migration may carry exact bytes/rows into its feedback decision model only if candidate identity can be resolved. Keep unresolved rows as opaque legacy decisions; never invent a `false_positive` or `intentional` reason and never delete the source as a side effect. |
| New finding feedback and Semantic candidate dismissals | `meta/proprium/plugins/proprium.diagnostics/feedback.yaml` (DESIGN_TARGET) | Sole destination for new versioned decisions, including Semantic candidate dismissals. Use Host proposal and complete finding/evidence identity, never a mutable positional offset. Unknown root/entry fields round-trip unchanged. |
| Worker and result caches | Host `workspace.derived.cache`, scoped to Diagnostics plugin | Disposable and rebuildable. Never Git files, settings or correction history; cache loss changes latency only. |
| Active text, cursor, selection, undo and recovery journal | Host | Not in plugin cache or Git metadata. Plugin receives only the bounded data needed for the requested run. |

`feedback.yaml` v1 has root `{schemaVersion: 1, entries: [...]}`. Each active entry has `id`, `findingFingerprint`, `decision` (`false_positive | intentional | deferred`), `source` (`repositoryId`, `branch`, `snapshot`, `evidence[]` where each evidence row has `path`, `fileRevision`, optional `entityId`, `textHash` and `span`, plus analyzer/config/model identity as applicable), `annotation?` (UTF-8 text up to 1000 bytes), `createdAt`, and `updatedAt`. A migrated unresolved source row may additionally be represented as `legacy_dismissed` with its original candidate ID/timestamp and no inferred reason; it remains visible for author reclassification and only suppresses an exactly resolved candidate identity. A `corrected` decision is not valid generic feedback: send a canonical fact correction to its owning plugin through its proposal API. An entry suppresses or annotates only the same fingerprint under the same source/config identity; it cannot suppress a new revision's finding. Applying feedback is an explicit Host proposal; rejecting leaves the Git tree unchanged. On a stale proposal, re-run or show the decision as pending against old evidence, never silently suppress the current finding.

Legacy settings under `.arcadia/`, `meta/` and `meta/scriptorium/` are preserved byte-for-byte during discovery and import. Import or relocation requires a separate Host-reviewed proposal with source and target revisions plus collision/round-trip evidence. The diagnostics plugin is not authorized to delete the old source after import.

Every result carries `repositoryId`, `branch`, `snapshot`, `sceneId?`, `documentPath?`, `documentRevision?`, `draftGeneration?`, `textHash?`, `analyzerId+version`, `config/lexicon revision map`, `provider status map`, `complete`, and a typed `findings[]` or statistics payload. Each provider status is one of `ready`, `unavailable`, `disabled`, `failed`, or `stale`; the report also marks incomplete scans and unavailable sections explicitly. A finding carries stable `fingerprint`, `class`, `kind`, `severity`, deterministic/inferred basis, rule/analyzer version, source file/entity IDs, source revision(s), text hash when prose-derived, optional UTF-16 `{start,end}` range, bounded quote, evidence source references, confidence only for an inference, explanatory message and available next action. UI display labels never substitute for these machine fields.

Findings are ordered first by class (`structural`, `declared_continuity`, `format`, `statistical`, `hypothesis`) and then by severity, source order and stable fingerprint. A hypothesis cannot sort ahead of a blocking structural error due only to model score. Offsets are zero-based UTF-16 half-open indexes into the exact body string named by `textHash`; frontmatter offsets are excluded from the editable body and each finding includes the body origin. A changed body hides its old positional decoration immediately and labels any retained list stale until recomputation.

## Public action contract

The Host supplies workspace, branch, snapshot and cancellation context. Inputs cannot select another repository or substitute a revision. Every output echoes the exact observed snapshot, source revisions/hashes and completion status. All read/compute calls are logically idempotent for identical inputs and snapshot; implementation may cache only by the full identity above. Effects are `read` or `propose`; plugin actions have no `apply`, file-write, Git, network or publish effect.

All actions reject extra fields and validate bounded string, list, path and byte sizes. Read actions accept the Host cancellation signal; cancellation stops further page reads and Worker work and releases capability leases. A canceled/stale result is not cached as complete. Use Host error codes `invalid_input`, `unsupported_schema`, `scene_not_found`, `snapshot_stale`, `conflict`, `missing_capability`, `plugin_unavailable`, `capacity`, `cancelled`, `timeout` and `storage_unknown`; details identify bad path/config, missing file, provider, or conflicting idempotency key. Stale data requires refresh; never remap it to a successful empty report. Configuration parse errors point to file and field, preserve source bytes, and never masquerade as default configuration.

| `declared_continuity` | Inference-free comparison of explicit tracked states and ordered scenes: `non-adjacent-location`, `item-owner-mismatch`, `unrecorded-teleport`, `timeline-reversal`, `timeline-gap`, `travel-impossible`, `travel-severe`, `travel-tight`. | `statistical` | Rhythm streak ≥3 matching normalized endings among narration sentences (dialogue breaks a streak); tone vector deviation only when intended tone is declared; plot goal lexical divergence only when enough content terms exist; prose-balance ratios; sentiment arc; term variants, unknown terms, repeated phrases and habits. Report measurement/threshold, never truth. |
| `hypothesis` | LLM/semantic first-read or contradiction candidate, only after explicit action and any required disclosure/consent. Return source quote pair, path, revisions, rationale, verdict `contradiction | compatible | insufficient | unreviewed`, model/provider identity and uncertainty. A `contradiction` verdict remains an author-review hypothesis. |

No LLM, remote service, embedding or downloadable model is required. This canon does not set source model names as a dependency. External inference may only come from the separate consented Paired Writing path; local semantic candidates use Semantic's opt-in lifecycle. A provider timeout or refusal leaves the local diagnostics view usable.

## Change, idempotency and recovery rules

- Every diagnostic, selection, filter, chart and navigation is read-only. A user decision becomes a `ChangeSet` proposal with read/write set, expected path/file revision, source finding fingerprint, text hash, exact diff and idempotency key.
- The Host owns proposal display, approval, rejection, stale detection and apply. Diagnostics cannot edit the worktree, editor buffer, recovery journal, Git tree, author feedback file or remote branch itself.
- The Host applies a feedback or manuscript proposal only after the author approves it in the standard Review UI. A rejection or canceled review changes no source file. Approval still does not imply a local checkpoint or GitHub publication.
- Draft analysis accepts the active buffer as an ephemeral read input. It may display current-Draft findings, but a proposal must bind to the Draft generation and saved base revision; if either changed, Host Review requires a refreshed diff. Diagnostics must never restore a saved result over IME composition, selection, undo history or a newer Draft.
- On reload, accepted feedback is re-read from Git and compared with its full finding identity. Browser cache loss simply recomputes. No migration clears old paths. A malformed feedback/config file stays intact and is reported for user repair.
- A timeout, worker crash, capability loss or page interruption leaves source and any already submitted proposal intact. Retry first queries the stable proposal key/status; it never creates a second write or claims an uncertain proposal applied.

## UI and author flows

The existing Host-owned CodeMirror editor, Desktop/Mobile shells, typography and Draft recovery remain mounted. Diagnostics supplies validated descriptors and bounded result data; Host components render them. The plugin provides no HTML, CSS, editor, global keyboard handler or direct navigation implementation.

**Desktop:** show a narrow, non-blocking margin/gutter marker for the current scene and a `診断 / 根拠` view in the existing Context/Inspect or Review panel. The panel lists summary counts, provider states, grouped findings, severity/kind filters, sentence/kind ordering, and stale/loading/canceled states. Selecting a prose finding invokes Host navigation to its UTF-16 body range and reveals a bounded quote plus the rule, threshold, config revision and source. Structural findings navigate to the exact YAML/Markdown file and field. Two-source hypotheses show both evidence blocks and separate scene-jump controls. A proposed fix opens normal Host Review with before/after and complete file path/revision.

**Mobile:** show a compact status marker and a scrollable `診断` sheet. Tapping a row closes or backgrounds the sheet and asks Host to select the exact source; Back restores the same scene, selection, scroll/page and caret. Return must not remount the editor or discard Draft/undo/IME composition. Filters remain touch-accessible; no hover-only explanation, drag-only action or forced keyboard open. Rejecting/closing the sheet leaves the same text editable.

The panel labels four states distinctly: `current`, `updating/stale`, `partial (provider unavailable)`, and `failed`. A list from a previous revision may remain visible during recomputation only with stale labeling and disabled navigation to invalid ranges. No result is called “clear” when a requested provider failed or the scan is incomplete. The Host preserves collapsed-section preferences locally; plugin preferences do not become Git data unless explicitly proposed.

## Execution, dependencies and delivery

```text
H0 Host: typed revisioned reads + Draft context + action registry + Proposal Review + rendered panel/decorations
  └─ Narrative P0: scene/path resolution and snapshot identity
       └─ Diagnostics P1
          ├─ optional Research: tokenizer, term aliases/variants, lexical source
          ├─ optional Knowledge: declared entities/world events/relations
          ├─ optional Speaker: attribution and voice evidence
          ├─ optional Semantic: local embedding contradiction/reranking candidates
          └─ optional Paired Writing: explicitly consented external-model first-read hypothesis
```

There is no mandatory plugin-to-plugin dependency edge: consumers use versioned Host action capabilities at the same snapshot. Narrative identity is required for scene-aware grouping; without Narrative, text lint and generic file analysis can still run on a selected Markdown path. Missing/disabled/failed Research removes only morphology-derived features; Knowledge removes only declared story checks; Speaker removes voice sections; Semantic removes model candidates; Paired Writing removes external first-read. No fallback may silently substitute another model or weaken a deterministic check. Diagnostics never calls the Gateway directly.

Compute uses a signed WASM component in a Host-managed, terminable Worker. The Host provides paged revision reads, bounded current-Draft input, action invocation, navigation, proposal review, and a quota-bound `workspace.derived.cache`. The plugin has no DOM, direct IndexedDB/OPFS, Git, credentials, arbitrary network, background polling or arbitrary JS. UI uses declarative Host components. A tokenizer/WASM dictionary or model is lazy, optional and loaded only after an explicit analysis needs it; cancellation/disable releases worker and cache leases. Artifact digest/signature/publisher/ABI/capability admission follows the common Plugin Distribution and WASM ABI contracts. The old Node child-worker execution and package `manifest` are recovery evidence, not Proprium runtime requirements.
