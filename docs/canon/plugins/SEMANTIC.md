# Canon P2 — `proprium.semantic` (Optional Semantic Retrieval)

**Status: normative recovery and implementation contract.** Scriptorium contains a working server/Node implementation of these algorithms and actions; that source is recovery evidence, not a Proprium browser plugin. Proprium's signed WASM artifact, browser model runtime and author-facing integration remain `DESIGN_TARGET` until their acceptance gates pass. No model or network service is required to write, use exact search, or run the Research plugin's lexical tools.

## Product role and boundary

Semantic adds optional embedding retrieval, reranking, similarity clustering and prose-level contradiction hypotheses. It helps an author find related passages or review a possible inconsistency; it never establishes a fact, edits manuscript prose, creates a canonical relation, owns Git, or publishes. Search entry, lexical ranking, terminology and navigation belong to Research. Evidence review, continuity warnings and dismissal decisions belong to Diagnostics. Semantic is a lazy compute provider that Research and Diagnostics can request through the Host action registry; it does not provide a second search product or a second diagnostics store.

The signed plugin's stable identity is `proprium.semantic`; its public action IDs are listed below. It has no private UI panel. The Host renders Semantic's controls within Research search/results and Diagnostics evidence/review surfaces. A disabled, missing, incompatible or failed Semantic plugin leaves the lexical search field, prose editor, Diagnostics' deterministic checks and Host recovery available.

This split retains independent model/index lifecycle: Semantic can be disabled to release memory and delete derived vectors without disabling Research or Diagnostics. Search remains an immediate lexical operation; embedding modes are explicit. Atlas, hosted LLM contradiction verdicts, server-side index storage and provider credential management are outside this plugin.

## Snapshot, inputs and derived data

All Semantic requests use the Host Action Registry envelope from [Host/Plugin Contract](../HOST-PLUGIN-CONTRACT.md): immutable repository identity, branch, pinned local commit plus worktree generation, request ID, deadline, cancellation signal and capability lease. Default analysis reads saved worktree bytes and excludes unsaved editor Draft. A user may explicitly select the Host's current draft snapshot; that result carries its distinct `draft_generation` and is discarded on draft change. The guest cannot supply or replace workspace identity, snapshot, repository path, model digest or expected revision. Every response returns the same observed snapshot; Host discards it if the active selection or snapshot changed before rendering.

The Host's paged `workspace.file.list/read` is the sole source. For Arcadia-format projects, passage construction accepts canonical entity IDs/types/path/name/aliases and reads only recognized data at the pinned snapshot. The source extraction contract is preserved:

- Embeddable entity types: `scene`, `manuscript`, `character`, `location`, `item`, `faction`, `event`, `thread`, `lore`.
- Passage content order: non-empty canonical body, then string `description`, then string `notes`; each included field is trimmed and joined with one LF (`\n`), then the source sentence splitter trims each sentence and assigns its zero-based index within that entity.
- The lexical projection recovered for search includes entity name and aliases, body, normalized structured notes and `memo`, with source field weighting. That projection is now Research-owned. Unknown YAML keys, Markdown/frontmatter, aliases, notes, original bytes and non-Arcadia files remain untouched; malformed/unknown records are not rewritten to fit an index.
- A candidate passage reference is `(entityId, sentenceIndex, textHash, sourcePath, sourceRevision)`. IDs must be resolved from explicit story references. No file path is inferred from an ID.

The only persistent Semantic state is disposable derived data in Host `workspace.derived.cache`. Its complete cache namespace is `(pluginId, repository provider/immutable ID, owner scope, branch, remote commit, overlay/worktree generation, corpus generation, passage schema, splitter/tokenizer version, embedding model ID+revision+verified artifact digest, dimensions, index format)`. Vector key is `(entityId, sentenceIndex, SHA-256(UTF-8(exact passage text)))`. Cache membership stores source path and file revision for each passage; results are returned only when both passage and source revision still match. A cache miss, corrupt record, unsupported cache format, incomplete build or deleted source is reported as missing/stale and rebuilt from source. Cache writes stage a complete generation then atomically publish the generation marker; cancellation/failure leaves the previous valid generation readable. Cache never enters Git and can be evicted without data loss.

Source model identity is `Xenova/multilingual-e5-small@761b726dd34fb83930e26aab4e9ac3899aa1fa78`, 384 dimensions, using its fp32 `onnx/model.onnx` artifact (470 MB); the reranker is `mogolloni/bge-reranker-v2-m3-onnx@e5023553f6c47f09057da7a19cdd79ef850a4985`, using `onnx/model.onnx` plus its external data file (about 2.27 GiB). Keep this source-compatible fp32 embedding baseline; quantization is a new model identity and is not interchangeable without a new accepted quality/corpus gate. The E5 embedding artifact is the default optional retrieval model. Reranker is a separately opted-in high-storage/high-memory feature and is unavailable on a device that fails the published capability gate. These exact source files/revisions fix the algorithm baseline; digest values for every artifact file, tokenizer and runtime are generated and pinned in the signed plugin manifest. The E5 model is based on the MIT-licensed `intfloat/multilingual-e5-small`; the reranker declares Apache-2.0. The release must include license/provenance metadata for the exact files before fetching or running them. The plugin cannot trust a model URL, model name, registry response or digest alone as publisher authentication.

Pinned upstream artifact manifests: [Xenova multilingual E5 small](https://huggingface.co/Xenova/multilingual-e5-small/tree/761b726dd34fb83930e26aab4e9ac3899aa1fa78/onnx) and [BGE reranker v2 M3 ONNX](https://huggingface.co/mogolloni/bge-reranker-v2-m3-onnx/tree/e5023553f6c47f09057da7a19cdd79ef850a4985/onnx). The embedding artifact plus tokenizer/config files is approximately 500 MB total; the reranker package is approximately 2.27 GiB. Host consent UI displays the exact signed-manifest total, not these rounded source-site figures.

Both model prompt inputs preserve Scriptorium's exact embedding transform: prefix every sentence and query with `passage: `, run the pinned tokenizer/model with mean pooling and L2 normalization, then rank by cosine similarity. Do not silently switch to E5 `query: ` prefixes, another pooling rule, quantization or a different sentence splitter; each changes model behavior and cache identity. Reranking sends each query/candidate pair through the pinned BGE tokenizer as `(query, text_pair)`, with padding and truncation, and returns `sigmoid(logit)` per candidate; sort by descending score and retain original order for ties. Rerank output is a relative ordering aid, not a calibrated probability.

No author setting, terminology record, dismissed candidate, correction, prose or source YAML is stored in this derived cache. Existing Scriptorium files `meta/scriptorium/modules/semantic/settings.json` and `meta/scriptorium/modules/semantic/contradiction-dismissals.jsonl` are recognized as legacy author state for import/audit only: keep their bytes and unknown fields, never overwrite or delete them during activation. The reranker preference moves to Host's local per-user plugin preferences. Because the old preference is workspace-file state and the new one is browser-profile state, adoption is explicit: Host says that the imported setting will apply across this user's workspaces, and the user may adopt or dismiss without editing the legacy Git file. Accepted term-group proposals remain Research-owned; dismissal proposals and migration conflicts remain Diagnostics-owned. Legacy dismissal migration preserves bytes until an explicit Host-reviewed conversion to Diagnostics' `meta/proprium/plugins/proprium.diagnostics/feedback.yaml`; a collision reports both versions and performs no write.

## Public actions

The public action names below are versioned contracts. `read` includes bounded pure analysis and disposable cache/index writes. `propose` is used only when an action submits a canonical workspace change; Semantic has no `apply` action. All object inputs are strict (unknown fields rejected), UTF-8, size-bounded and schema-versioned. Host binds scope, snapshot, generation, caller and cancellation; guest input cannot override them. Descriptors declare whether the action accepts `ui`, `mcp` or `plugin` callers and whether a user gesture is required. `index.status`, `settings.read` and `task.status` allow `ui,mcp,plugin`; index rebuild and task cancellation allow `ui` only and require a user gesture; the settings adapter allows `ui` only with a user gesture; passage query and rerank allow `ui,mcp,plugin` only when the required artifacts are already admitted; term clustering allows `plugin` from Research or `ui`; contradiction candidates allow `plugin` from Diagnostics or `ui`. ## UI and author interaction

Semantic has no independent tab. Host surfaces:

- Research's existing search field has lexical, hybrid and semantic modes. Lexical is default, returns without model activation and remains usable offline. Hybrid/semantic modes show whether the local index is missing, stale, building, ready or unavailable; they never block typing. The result row labels source scene, sentence, lexical/vector/rerank score components and index/model revision. Selecting a result asks Host navigation to open exact file and sentence and retains the editor's dirty draft, IME composition, caret, selection, undo history, scroll and reading position. Stale results are disabled until refreshed.
- Research's expression mode uses the same query and results list; a sentence locator and reason label explain the expression filter. It is not another panel.
- Research's term-candidate view may show `semanticOnly` clusters separately from deterministic reading/string matches. No cluster automatically changes aliases, glossary files or prose. Author selection opens Research's one Host ChangeSet review and preserves ignored/unselected terms.
- Diagnostics' contradiction view combines Semantic sentence-pair hypotheses and Diagnostics deterministic warnings, clearly labels source (`embedding` or `declared continuity`), quotes both records, shows model/version and score only for embedding candidates, and offers separate `Open source A`, `Open source B`, dismiss and refresh controls. A high similarity number is not a contradiction verdict. Host owns dismissal proposals and their revision checks.
- On mobile, use a bottom sheet or focusable panel reached from the active editor; rows have large source-jump and close/return controls. Closing restores the exact same manuscript selection and does not disturb the on-screen keyboard. All controls have keyboard/touch alternatives and visible loading, canceled, offline, stale and error states.
- The reranker toggle is a Host-rendered preference form bound to `plugin.preferences` key `reranker.enabled` (`boolean`, default `false`, nonsecret browser-local user partition). Guest code can read but cannot write the preference. The legacy UI action only routes to the form with a pending value; it never applies the value itself. Changing the preference does not write Git, trigger a download or grant model capability.
- Before any first model transfer, show exact artifact identity, verified byte size, required storage, expected local compute, project-text locality, cache clear behavior and explicit start/cancel. No model download occurs on page load, plugin enable, lexical search or background polling. If the approved artifact is unavailable, render `semantic unavailable` and keep lexical search/editor active. An MCP/plugin read request cannot cause a missing artifact to download; Host returns `provider_unavailable` until a user explicitly admits/downloads the asset.

Navigation is Host-owned and must pass the existing dirty-editor guard. A superseded result, canceled task, changed workspace, stale snapshot or disabled plugin cannot move focus or replace editor contents. No semantic highlighting is injected into the editor unless the Host provides revision-bound, removable decorations; none is required for V1.

## Dependencies and runtime lifecycle

Hard dependencies: Host Action Registry, revision-pinned paged file reads, derived-cache broker, capability query, negotiated model access and Worker cancellation. Its only plugin-level dependency is Research's stable term-candidate protocol; enable Research before Semantic. For clustering, Host dispatches Research's current candidate result to `semantic.terms.cluster`; there is no direct module call. Semantic never imports Research's or Diagnostics' implementation or state. Research's own UI and lexical workflow may ask the Host to compose Semantic results with Research lexical results, but Research does not call Semantic from a Research action. This keeps the plugin activation DAG acyclic. Diagnostics optionally consumes contradiction candidates through Host action dispatch; it owns review dismissal state. Semantic settings read from the `plugin.preferences` capability; only Host's validated preference form writes there.

Optional dependencies: admitted embedding artifact for vector query/clustering/contradiction hypotheses; admitted reranker artifact for reranking; Research passes term candidates at invocation. No Gateway, login, external API, remote inference service, LLM, WASM threads, WebGPU or continuous model worker is required. CPU fallback is allowed only when the signed plugin contains a tested supported runtime; unsupported mobile device/memory reports unavailable.

Compute runs in an independently terminable Worker owned by the Host plugin runtime; the WASM guest has no DOM, browser storage, Git, credentials or arbitrary network. The Host broker exposes only snapshot reads, derived-cache calls, bounded model artifact access and typed results. Artifact identity, signature and digest are verified before guest execution. Model artifacts are static, immutable, licensed and digest-bound by the signed publisher manifest. Download/activation are user initiated. Worker is created lazily for indexing or explicit semantic query; disable, navigation cancellation, timeout or artifact failure terminates jobs, releases leases and leaves editor and other plugins alive. A synchronous guest loop is stopped by Host Worker termination; no absolute CPU/memory quota is promised on browsers.

No background polling. Job batches are bounded by Host policy; source behavior used embedding batches of 32, rerank batches of 8, at most 30 rerank candidates and 100 vector hits. Proprium conformance must test its chosen caps on supported devices rather than rely on those legacy numbers. `index.rebuild` uses a staging generation; complete only after all vectors and source references validate. Interrupted/stale generation is discarded; previous valid cache remains readable.

## Acceptance

These are required observable outcomes, not source-test names. Implementations must pass every applicable gate on actual supported desktop Chromium and mobile WebKit/Android classes; a Node source test or WASM build alone cannot pass.

<a id="accept-sem-a1"></a>

### SEM-A1 — Index lifecycle and data isolation

With a synthetic work containing 120 passages across story and manuscript files, status initially reports missing without loading the model. The author explicitly starts indexing; progress reaches 120 and final status is ready for the selected snapshot. A second build reuses unchanged vectors and replaces only the edited passage. A changed branch/worktree generation returns no old hit as current; a stale/missing/corrupt cache rebuilds from Git source. Cancel mid-batch, Worker termination, tab reload, storage quota failure, offline missing model, plugin disable and re-enable each preserve the previous complete generation and source files; tasks stop and leases release. Repository A's cache never appears in repository B.

<a id="accept-sem-a2"></a>

### SEM-A2 — Search and reranking

From Research, run a Japanese lexical query while Semantic is absent/disabled/offline; lexical result appears immediately with no model request. Enable hybrid mode and query a known fixture; Research combines lexical and vector ranks by RRF with component scores, cites exact current revision and opens the exact sentence. An outdated response after editing or switching branch is marked stale and cannot navigate. Request reranking only after explicit opt-in; a valid local run returns finite model-tagged scores, while unavailable artifact/device/cancellation returns original order plus a visible warning and preserves editing. Repeat the same query/snapshot/model produces same ordering and does not leak across repositories.

<a id="accept-sem-a3"></a>

### SEM-A3 — Expression results

Given pinned sentences containing descriptions, nouns-only lines and empty lines, expression search ranks sentences containing verbs, adjectives or adverbs ahead of the remaining retrieved sentences, using the Research tokenizer; it does not discard the remainder. User can open each exact source span and return to the original Japanese text selection on desktop and mobile. Missing tokenizer or model shows unavailable state; ordinary search is unchanged.

<a id="accept-sem-a4"></a>

### SEM-A4 — Term clusters and author authority

Given same-reading and edit-distance pairs plus unrelated Japanese terms, deterministic clustering yields the expected canonical term ordered by occurrence/source count; embedding-only `海岸`/`浜辺` pair is marked `semanticOnly`. With model disabled, only deterministic clusters remain. A cluster never writes `bible`, `meta/synonyms.yaml` or prose; selecting a proposed alias opens Research's revision-bound Host review. If source candidate revision changed, Host rejects stale proposal and keeps all source bytes/unknown YAML keys intact. No LLM is required.

<a id="accept-sem-a5"></a>

### SEM-A5 — Evidence and contradiction review

Given two prose sentences mentioning the same declared character with a cosine score inside `[0.29,0.84)`, Diagnostics shows two exact quotes, source paths, sentence indices, snapshot, score/model provenance and uncertainty; each jump opens that sentence without losing the active draft. Deterministic ownership/teleport warnings appear once from Diagnostics, not a second copy from Semantic. Same-passage and unmentioned passages do not create embedding pairs. Missing/stale index still displays rule warnings and an explicit build path. A stale candidate cannot be dismissed; dismissal is a single Diagnostics-owned proposal and conflicting changes preserve both source and author decision for review. On mobile, dismiss/open/return controls work without drag or keyboard focus loss.

<a id="accept-sem-a6"></a>

### SEM-A6 — Preference and privacy

On a fresh browser profile, model and reranker are unloaded and `reranker.enabled` is `false`. A user gesture through the Host preference form changes the browser-local preference; reject/close keeps the old value, reload preserves the accepted value in that user partition, and no Git file is written. Calling legacy `semantic.settings.update` from MCP/plugin is denied; a UI call only opens the Host form with a pending value. Preference change alone does not download or activate a model. Disconnect network after artifact caching and reranking continues locally. Instrumented network shows no project-text egress and no fetch until author requests an admitted artifact; a missing/invalid digest fails before guest execution.

<a id="accept-sem-a7"></a>

### SEM-A7 — Legacy recovery and complete author loop

For a fixture holding Scriptorium `settings.json`, `contradiction-dismissals.jsonl` and unknown JSONL fields under preserved legacy paths, opening the repository makes no edits. Host displays the old reranker value and says adopting it will apply profile-wide; choosing adopt stores the boolean only in the local plugin preference, while choosing dismiss or encountering invalid JSON leaves the value unapplied and source bytes unchanged. Diagnostics' explicit migration preview identifies each dismissal and destination owner; it carries resolvable rows to `feedback.yaml` as `legacy_dismissed` decisions or displays a collision with both revisions, and Host leaves unknown bytes unchanged. Disabling/uninstalling Semantic evicts only derived vectors and local model lease, never clears these author records. Run search → evidence jump → return to draft → cancel model task → reload; prose, IME/editor selection and local draft recovery remain intact. Plugin absent, disabled, invalid signature, ABI mismatch, guest trap, cache eviction, offline restart and mobile memory pressure all retain generic file editing and lexical Search.

## Completion and limits

Semantic is complete only when all `SEM-01..SEM-09` ledger rows have their linked acceptance gates passing, Research/Diagnostics render the real user-facing paths, the independently signed plugin installs and upgrades without a Host rebuild, and provenance/licensing for exact model artifacts is verified. Legacy Scriptorium package tests establish algorithm/source behavior only. No present Proprium browser, signed-artifact, mobile-device or model-cache result is implied here.


All source-bearing Semantic query/contradiction results include `evidence:SourceSpan[]` in addition to their display fields. Sentence splitting and trimmed/concatenated entity fields retain an original-file offset map; original path/hash/UTF-16 spans and exact unnormalized quotes are mandatory before Host navigation. Scene-level aggregate hits retain at least one contributing cited sentence. Evidence B in a contradiction has the same fields as evidence A, never an inferred uncited counterpart. Contradiction pages default to 50 and cap at 100, deterministic score then candidate-ID ordering; cursor binds snapshot/model/config and a changed identity returns `snapshot_stale`. Large reports use bounded pages/sealed artifacts under H0 limits. Signed `models[]` metadata in settings is `{id,revision,digest,byte_length,role:embedding|reranker,dimensions?,license,status}` and never executable URLs or credentials.
