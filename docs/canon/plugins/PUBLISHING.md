# Canon P2 — `proprium.publishing` (Local Export and Publication Metadata)

**Status: normative recovery target.** Scriptorium has working local export code, publication-episode metadata and a server-backed read-only share path. Those sources do not establish that the Proprium WASM plugin, static export delivery, or a share service exists. Basic TXT and EPUB export are an early authoring deliverable after H0 and Narrative; the advanced print, episode-map and optional sharing surfaces remain P2. See [plugin architecture](../ARCHITECTURE.md), [Host contract](../HOST-PLUGIN-CONTRACT.md) and the [recovery inventory](../RECOVERY-INVENTORY.md).

## Product role and priority

Publishing lets an author select a coherent work range, inspect it, and produce a local reader-facing file. It also records the author's mapping between source chapters/volumes and publication episodes. It never edits manuscript content, creates a Git commit, pushes to GitHub, or claims an export is remotely published. Episode-map changes are ordinary reviewable Git metadata proposals.

`proprium.publishing` is one independently installable plugin because its export formats, episode mapping and optional reader sharing consume the same validated work tree and publication scope. Sharing stays an optional capability inside Publishing: its distinct external network/token authority is isolated behind a Host adapter and cannot block local exports. Publishing depends on Narrative's scene and manuscript identity; it has no model, Gateway, login, network, Speaker or Semantic dependency. TXT and EPUB must be implemented first within this plugin and work offline. P2 applies to the broader Publishing surface and cannot postpone those two formats.

The plugin does not upload prose, operate a posting-site account, post chapters to an external platform, make public URLs by guessing a deployment origin, or own a public server. Scene-level export is not present in either recovered export workflow; export scopes are exactly `all`, `volume`, and `chapter`. Scene-level scope exists only for the optional share-grant model.

Publishing consumes only Narrative's validated, paged hierarchy and the exact `manuscript_path` it returns; it never derives identity or body paths from folder names. Propagate Narrative diagnostics with their source path. Reject an unsafe path, absolute path, path traversal, non-Markdown scene body, invalid YAML/frontmatter, duplicate episode/grant ID, or stale reference with a path-specific error. Missing linked manuscript content is `file_not_found` with `details.reason: missing_source`; it cannot silently become an empty scene in a successful export. Empty existing Markdown is valid but is called out in preflight. Export uses Narrative's canonical tree order without a second sort. Scriptorium's old folder/title fallback and comparator are recorded as recovery evidence only; Narrative owns the Proprium identity and ordering contract.

Every read, preview and export is bound to Host `scope` and one pinned `SnapshotRef` (repository, branch, remote commit, overlay/worktree generation). The Host first flushes the active editor or offers to export the last saved snapshot. The confirmation names whether selected bytes include an unsaved Draft, local checkpoint, or confirmed remote commit and warns that local work may be lost. The result repeats that snapshot and source class. A snapshot change during work cancels/rejects the result as `snapshot_stale`; the Host never switches or replaces editor text to make the export run.

These active Scriptorium module metadata files remain canonical author data at their current paths; renaming the runtime plugin does not move them. Publishing reads and proposes edits at these exact paths. Flat/retained migration files are surfaced by Host recovery inspection, not silently treated as alternate live sources. If an import target already exists with different content, return `conflict` with `details.reason: metadata_conflict`, show both paths/revisions and require explicit reviewed resolution; never choose by timestamp, concatenate lists or overwrite implicitly. Missing active files read as empty and create no file; available older recovery sources are surfaced separately. A reviewed import includes the source revision and active target revision/absence in the Host read set, retains exact source bytes and unknown fields/comments, and never deletes a source. For episode edits, the complete submitted known-entry list removes omitted entries; unchanged known/unknown values survive by stable ID. `publishedAt: null` clears only that date and `sceneIds: null` clears only those annotations. New UI dates use `YYYY-MM-DD`; untouched valid legacy timestamps remain unchanged. Reject duplicate IDs/numbers, absent scope IDs, chapter annotations outside their selected chapter and invalid positive episode numbers.

Share descriptors stay at their existing canonical path; any older retained source is imported only by Host recovery with the same explicit conflict rules. They contain only a hash of the high-entropy bearer. Unknown non-secret extension fields survive; sensitive-looking fields (`owner`, `user`, `token`, `bearer`, `secret`, `credential`, `auth`) are neither newly accepted nor copied into a new canonical record. Legacy bytes remain untouched for recovery. The Host owns token lifetime; raw tokens never enter Git, plugin inputs/outputs, logs, telemetry, browser history/referrers, caches or MCP. A reader serves a link only when the single Host-configured provider verifies its descriptor against the repository's current remotely confirmed branch/head, expiry and revocation state. A local proposal/checkpoint is never public.

No Publishing index or model cache is required. A bounded in-memory parsed tree/preview may be discarded on plugin disable. Export artifacts are local ephemeral outputs and never enter Git or plugin cache by default.

### Preconditions, cancellation and errors

- All actions require an installed, enabled plugin and an admitted artifact digest. The tree/export actions require Narrative's current tree and the Host paged file reader. EPUB appendix generation optionally reads Knowledge-owned files directly through the same snapshot file-read capability; it does not invoke Knowledge internals.
- Exports require a validated non-empty selected range, source availability for every selected scene, safe paths, and current snapshot. Preflight warnings are not a blocker. Invalid range or empty scope returns `invalid_input` with `details.reason: invalid_scope|empty_scope`; a missing source path returns `file_not_found` with `details.reason: missing_source`; invalid markup/source metadata returns `unsupported_format` with `details.reason: invalid_source`; unsafe cover returns `invalid_path`; missing/unsupported optional cover returns warning and continues without cover.
- A cancellation signal stops further page reads, ZIP generation or artifact writes, deletes the incomplete ephemeral artifact, and leaves source/Draft/Checkpoint intact. If the browser cannot abort the final native print dialog, cancellation closes the preview and returns focus to the originating panel; it does not alter the document.
- All failures use the common Host error code set. This plugin adds `details.reason` values `invalid_scope`, `empty_scope`, `missing_source`, `invalid_source`, `metadata_conflict`, and `artifact_unavailable`; concurrent divergent metadata uses `conflict`, stale narrative identity uses `ambiguous_identity`, an absent share service uses `provider_unavailable`, and an absent/untrusted Narrative dependency uses `dependency_unavailable`. `snapshot_stale`, `capacity`, `artifact_too_large`, `cancelled`, `timeout`, `plugin_unavailable`, `capability_denied`, `storage_unknown`, and `external_state_unknown` retain Host meanings. Errors identify a source path/scene where safe, never include content from another repository, and never imply successful delivery.
- Every action uses a snapshot captured once at request start. A cancel, tab suspend, worker termination, repository switch or changed snapshot prevents late UI output; the user remains in the same document and focus/selection/IME state.

`proprium.publishing.export.plaintext`, `proprium.publishing.export.epub`, and `proprium.publishing.export.vertical-print` are `read` actions: they read the pinned workspace and write only the request-scoped ephemeral artifact. Download and native print are separate Host effects requiring a fresh user gesture; an MCP caller receives artifact metadata only. `proprium.publishing.export.plaintext` preserves source manuscript syntax by default. `strip` removes ruby readings and bouten delimiters while keeping base text. `kakuyomu` writes `｜base《reading》`; `narou` writes `|base《reading》` and converts bouten to per-character Narou notation. Modes are mutually exclusive. Filenames combine sanitized work title, scope label and mode suffix. Text is UTF-8 without frontmatter.

`proprium.publishing.export.epub` produces EPUB 3 with stored `mimetype`, `META-INF/container.xml`, OPF package metadata, navigation, a title page and one XHTML item per selected scene in canonical order. It escapes XML text, converts supported ruby to `<ruby><rt>` and bouten to a styled span, keeps Japanese Unicode, and emits deterministic valid NCName identifiers. Optional cover is included only for the supported image MIME types. Optional Bible appendix includes ID-bearing characters, lore and locations (name/title, aliases and supported notes); it excludes id-less helper YAML and does not write back to Knowledge. Output must pass EPUB structural validation and be opened by an EPUB reader during browser acceptance.

`proprium.publishing.export.vertical-print` writes ordered scene titles and body text to a scoped ephemeral UTF-8 artifact. The Host reads that sealed text as text data and renders it with its safe vertical-writing component; guest output is never interpreted as HTML. Host UI exposes exact preset IDs `bunko`, `web-novel`, and `genko`, mapped to Host typography values; a preset changes only the print preview. User selects Print/Save as PDF from the browser's native dialog. Physical pagination and printer-specific output are not guaranteed. Loom's five preflight checks are displayed immediately before a user confirms export or print; they reset for each dialog open, have a non-blocking warning while any remain unchecked, and provide a separate Cancel control.

## UI and author continuity

Publishing surfaces appear as Host-rendered panels and commands, not a second application shell. Desktop groups “書き出し”, “EPUB 書き出し”, “縦書き PDF”, and “公開回マッピング” in the Publishing section; “共有リンク” is visible only when a share service is configured and trusted. Use the Host's `OutlineTree`, forms, `ReviewPanel`, status and confirmation dialog. The plugin supplies data and commands, never React/HTML/CSS from its publisher.

The export form starts with the first recovered safe operation: plain-text download. It shows `全文 / 巻 / 章`, a volume/chapter selector, explicit markup mode, a preflight action, and a generated filename/snapshot before download. EPUB adds optional title/subtitle, cover path and appendix checkboxes. Missing cover is a warning with an option to continue without it. Vertical print shows a vertical preview, scope, one of the three typography presets, “印刷 / PDF”, and the browser's print dialog. While work is empty or loading, export/print controls are disabled with a reason; error state includes Retry after the source becomes available.

The episode panel lists episodes by number then ID and supports add, select, reorder-by-number, edit, scope, optional chapter scene annotations, date clear, remove, and “レビューに保存”. Before Host review it shows a proposal summary; the user can inspect the complete YAML diff, approve or reject. The panel labels the resulting state as “提案中”, “ローカルに適用”, “ローカルコミット済み”, or “GitHub公開済み” only when Host confirms each state. Saving a proposal does not claim the episode was posted to an external site.

If a share service exists, the owner-only panel shows service identity, scope preview, expiry, active/pending/revoked state, one-time URL reveal/copy, and an explicit owner action for create/revoke. Before create, it explains that a read-only bearer link grants access to the selected scope and expires at the chosen time. A created link is labeled **pending remote publication** until GitHub confirms the grant's exact commit. A rejected/unpublished proposal never makes a valid reader link. Revoke becomes effective only after its metadata reaches the remote snapshot; until then the UI warns that an already-issued link remains active. The public reader shows scope/title/expiry, a navigable chapter list, and the selected scene in reading typography; invalid, expired, revoked, unpushed, or out-of-scope requests produce the same non-disclosing unavailable response. It uses `no-store`, `noindex,nofollow`, and `no-referrer` and never includes an edit affordance.

On Mobile, the same actions are available in a full-width sheet with thumb-reachable controls and scrollable scope/episode lists. Native file download and print actions require a direct user gesture. Closing the sheet returns to the same manuscript, caret, selection, scroll position, undo history and IME composition. No asynchronous tree/export response may remount the editor or move focus. In offline mode, TXT/EPUB/print work from cached source; episode proposals can be reviewed/applied locally but show local-only status. Share controls say “sharing service unavailable offline” and never construct a plausible but unreachable URL.

Keyboard users can move through controls in document order, activate buttons without a pointer, and always see focus. Desktop shortcuts belong to the Host and remain unchanged. Mobile controls include text labels rather than drag-only ordering; reorder has up/down controls. Preflight checkboxes and warnings expose accessible names/`status` semantics. Export errors are `alert`s, progress is a status region, and cancellation returns focus to the action that opened the sheet/dialog.

## Dependencies, runtime and distribution

**Required:** Host identity/snapshot, paged `file.list/read`, typed action dispatch, local artifact delivery, Host panel renderer and review/apply flow; `proprium.narrative` action `proprium.narrative.hierarchy.tree` at the same snapshot and its explicit manuscript path. `proprium.publishing.project.tree` delegates each requested page through the Host action registry with caller `plugin` and the same repository/snapshot; it cannot inspect Narrative private storage. The episode map can render with no episode entries. TXT export works without other plugins once Narrative is enabled. EPUB appendix is disabled when its source files cannot be read and explains the optional Knowledge data; basic EPUB remains available. No plugin-to-plugin private-storage access is allowed.

**Optional:** Knowledge-owned character/lore/location records for EPUB appendix and the one Host-configured public-reader provider. There is exactly one active provider/origin per static Host configuration; the browser route cannot select a provider or origin. The named logical interface below is a normative caller contract, not a claim that a deployable provider currently exists. Provider implementation, provisioning and its separately authorized GitHub read access are external prerequisites; none belongs to the Gateway. Without a configured provider, local share metadata remains readable and is marked `provider_unavailable`; create fails `provider_unavailable` before token creation or proposal, and revoke remains an offline metadata proposal. Sharing egress requires explicit Host consent for destination and scoped contents. Provider failure never blocks export.

### Share reader adapter (logical Host capability, version 1)

The plugin never performs direct network requests. Host exposes the logical adapter `publishing.share-reader.v1` only when the single provider and public Host origin are present in local static Host configuration, the selected repository is remotely bound, and the owner has consented to the stated scope. The URL cannot set provider ID or origin. The adapter/provider is external to this plugin and Go Gateway; this contract does not assert that a provider is deployed. Missing provider, local-only repository, unavailable branch or denied consent returns `provider_unavailable`/`capability_denied`; no fallback URL is constructed.

The following typed logical operations are Host-to-provider calls. The `secret_lease` is an opaque Host-only handle: it is never action input/output and never crosses the network. The Host resolves it just in time to set an Authorization bearer header over TLS to its configured origin. Every call is limited to the bound `repository_id`; draft, checkpoint, overlay and local commit fields are removed before egress:

| Operation | Request | Result |
| --- | --- | --- |
| `capabilities` | `{repository_id,branch,remote_commit}` (`remote_commit` is current confirmed commit or null; null is unavailable for public sharing) | `{available,service_id,origin,host_public_origin,reader_version:1,max_expiry_hours,reason?}`. `origin` and `host_public_origin` must exactly equal the two HTTPS origins in local static Host configuration; provider-supplied origin never changes routing. `available` is true only when it can read this remotely bound repository/branch and validate a current grant descriptor. `reason` when false is exactly `provider_unavailable|repository_unavailable|service_unavailable|external_state_unknown|unsupported_reader_version`; success has no reason. `max_expiry_hours` is an integer from 1 through 87,600. |
| `metadata` | `{service_id,repository_id,grant_id,secret_lease,cursor?,limit?}`; `limit` is 1–200 and defaults to 100. | `{remote_snapshot:{repository_id,branch,remote_commit},scope:{kind:"project"|"volume"|"chapter"|"scene",id},label,expires_at,items:[{id,kind,title,parent_id}],next_cursor}`. Provider verifies the bearer, grant and current remote state before returning only in-scope tree metadata. |
| `read_scene` | `{service_id,repository_id,grant_id,secret_lease,scene_id,expected_remote_commit,offset?,length?}`; `offset` defaults to 0; `length` defaults to 65,536 bytes and is otherwise 1–256 KiB. | `{remote_snapshot:{repository_id,branch,remote_commit},scene:{id,title,revision,total_bytes,offset,bytes:Uint8Array,next_offset}}`. Returns only the authorized scene's manuscript body bytes; a range may split a multibyte UTF-8 code point, so Host incrementally decodes adjacent ranges as specified by `workspace.file.read`. Offsets are UTF-8 bytes, separate from editor UTF-16 positions. |

`repository_id` is the Host-bound positive integer GitHub identity, never a legacy work/project ID; `branch` is the exact bound remote ref. The provider maps `(repository_id,grant_id)` to the branch recorded by the grant, then resolves that branch's current remotely confirmed GitHub head; it never trusts a client-selected ref or commit. New records in the existing canonical JSONL include numeric `repositoryId` and exact `branch`; `tokenHash` is lowercase-hex SHA-256 of the UTF-8 bytes of the encoded base64url bearer string (not the decoded 32 random bytes). Legacy grants without those keys may be mapped only to the service's confirmed default branch after an explicit repository identity match; otherwise they remain unavailable for recovery. For every metadata call and every scene byte page, provider recomputes SHA-256 of the supplied bearer and verifies it against `tokenHash`, repository/ref, grant scope, expiry and revocation at the current remote head. `expected_remote_commit` must equal the current head and response; branch movement returns `snapshot_stale` and metadata must refresh. Revocation at current HEAD rejects an older pinned commit, so old snapshots cannot bypass revocation. Pagination is bound to the returned commit and stale cursors fail. Provider sees no local draft/checkpoint/unpushed commit and client-supplied commit never proves publication.

The owner URL is `{host_public_origin}/r/publishing/{repository_id}/{grant_id}#token={bearer}`. The route and fixed provider are Host-owned and configured locally; query/path input cannot choose an origin. The Host strips the fragment from address-bar history before any request and creates a one-use secret lease; the static Host generic `readonly-reader` resolves it directly into the provider's HTTPS Authorization header. No action/guest receives the lease or bearer. No cookies, owner credentials, redirects to another origin, third-party assets or plugin-defined route/DOM are permitted. The Host reveals the token once only through its owner UI after review/apply, never in action output/transcripts/MCP, Git (only SHA-256 is in grant JSONL), cache, telemetry, exceptions or logs. Provider may retain bounded operational request data only; it cannot retain repository/workspace/Git-object bodies or indexes, and cannot return cached content after current expiry/revocation is observed.

Wire `401` for malformed, expired, invalid or revoked bearer has one identical body/status; wire `404` for out-of-scope and unknown scene has one identical body/status. Neither response identifies the grant, hash, owner, repository contents or scope. Provider unreachable returns `service_unavailable`; remote state that cannot be confirmed returns `external_state_unknown`; branch movement returns `snapshot_stale`. Reader Host sets `Cache-Control: no-store`, `X-Robots-Tag: noindex, nofollow`, `Referrer-Policy: no-referrer`, strips fragment/history before network, rejects cross-origin redirects and loads no third-party assets. New links remain pending until exact descriptor confirmation at the current remote head. Rejected/canceled proposals clear the one-use token reveal buffer. If the owner loses a URL after reveal, revoke and remotely confirm revocation before creating a replacement.

The `proprium.publishing.shares.create` flow first calls `capabilities` for the bound repository/branch/current remote commit and requires UI caller, verified gesture, active provider, explicit destination/scope consent and available capability before token generation. It binds Host `share.token.create` to `secret.token.create({purpose,scope,expires_at})`: the guest sees only `{handle,sha256}` and never receives the bearer; Host associates the one-use secret with this exact ChangeSet and reveals it only after Host review/apply. The grant ID is stable for retries; JSONL stores the hash plus scope, expiry, repository ID and branch. Provider has no mutation endpoint. The Host generic `readonly-reader` opens the exact `/r/publishing/{repository_id}/{grant_id}` route with no plugin DOM. The link is not active before the descriptor is confirmed at current remote head. Revoke changes only Git metadata through a Host proposal; after remote confirmation the provider must reject the grant on each request. If service is offline, revoke can still be prepared and local UI clearly says remote revocation is unconfirmed.

Compute/action and UI responsibilities:

- WASM guest: parse validated source records; compose text; transform markup; build EPUB ZIP; return bounded preview/metadata; propose episode/grant metadata. Heavy job work occurs in a terminable Worker with request cancellation.
- Trusted Host: render/export panels and preflight; flush or select draft snapshot; read bounded pages; issue proposal/review/apply; receive artifact chunks and seal/verify the artifact; expose a user-initiated local download; read sealed vertical-print text through its Host-only safe artifact preview/print stream; own browser print; gate owner-only share output and external service consent.
- No guest DOM, filesystem, Git, cookie, direct network, credential, commit, publication, arbitrary code contribution or private workspace cache is permitted. The standard Host action registry serves UI and MCP calls; share-token creation/reveal is owner-UI-only and never callable through MCP `plugin_call`.
- Publish an immutable, signed artifact and manifest with exact WIT/ABI range, capability list, license/provenance and artifact digest. Install is distinct from enable; enable is distinct from execution. TXT/EPUB compute activates only on explicit user action. Disabling/canceling releases the Worker and incomplete artifact but retains all source and proposals. Update/rollback cannot change author files.

The standard JSON action response cannot carry a long novel as an unbounded base64 value. Use the shared Host `artifact.create({media_type,filename,scope,snapshot})`, `artifact.append({artifact_id,sequence,bytes})`, `artifact.seal({artifact_id,sha256,total_bytes})`, and `artifact.discard({artifact_id})` contract. Chunks are at most 256 KiB; the default total is 128 MiB per job, one artifact per plugin, and Host must disclose the negotiated cap before export. The Host validates contiguous sequence, exact size and digest, then offers a sealed immutable artifact only through a user-initiated browser download. MCP receives metadata, hash and availability, never an automatic download or print. Host-owned preview reads the sealed vertical-print text through its safe text-only artifact preview/print stream, never as guest HTML. Cancellation, workspace switch, quota exhaustion, `ENOSPC` or seal mismatch discards only the incomplete artifact and returns the exact Host error (`capacity`, `artifact_too_large`, or `storage_unknown` as applicable); Draft, checkpoint and repository files survive. Publishing does not choose hidden IndexedDB/OPFS authority or retain export bytes after download/dismissal. See the adopted [Host artifact contract](../HOST-PLUGIN-CONTRACT.md#artifact-delivery-external-providers-and-consent).
