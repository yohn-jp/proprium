# Host/Plugin Contract — Required Recovery Extensions

## Status and authority

This is the **normative contract** for authoring plugin portability. The v1 Host remains a compute-demo interface and is **insufficient on its own for a Narrative IDE**; the separately versioned v2 WIT, runtime, typed Host actions and official plugin build path are implemented. This document states complete required behavior, not an unconditional claim that every optional provider, device or live deployment has been verified. Implement remaining gaps generically in the Host rather than embedding Story Knowledge logic into trusted Core.

### Implemented boundaries and remaining certification (do not misreport)

- The legacy `app/src/browser/proprium/plugin-runtime/wit/main.wit` exposes demo-scale v1 snapshot/propose and title-only UI contributions. The incompatible `plugin-runtime/wit-v2/main.wit` declares `proprium:plugin@2.0.0`; `plugin-runtime/v2/`, `authoring/service.ts` and the Host-side schema/Writer implement the versioned typed authoring route. Neither ABI silently alters the other.
- The v1 `PluginPanel.takeSnapshot` still has a **256-file / 2 MiB** eager-read limit. Authoring v2 uses a separate paged, pinned file reader and Host-rendered declarative surfaces; the v1 limit must not be presented as a v2 full-work limit.
- `scripts/build-plugin-registry.mjs` supports both the original `example` compute-sum mode and `authoring` mode for the eight independently signed official plugins. Distribution availability requires a published signed registry and Host-pinned trust; build success alone does not prove a production installation.
- `gateway/mcp.go` exposes eight core MCP tools and forwards `plugin_call` to the active Browser Host. The Browser Host uses signed typed action dispatch for v2 authoring plugins; legacy v1 `run` remains separate. Live Gateway/provider conformance requires its corresponding integration and deployment evidence.

Keep both ABI versions separately verified; do **not** quietly change existing `proprium:plugin@1.0.0` semantics. The v2 Host's actual behavior, independent plugin conformance and optional services must each be evaluated against the acceptance matrix.

## Host-owned contract surfaces required

| Versioned family | Minimum typed operation | Invariants |
| --- | --- | --- |
| `workspace.identity.read` | repo ID, branch, current pinned commit+overlay, workspace/generation | plugin may not choose another repository implicitly |
| `workspace.file.list` | `{prefix?, cursor?, limit?} → {items, nextCursor, snapshot}` | bounded paging; stable deterministic path order and revision; no all-repo upfront load |
| `workspace.file.read` | `{path, snapshot, range?} → {bytes/text, revision/hash}` | exact snapshot scope and path validation; explicit binary/encoding error |
| `workspace.navigation` | `{target: {path?, sceneId?, panelId?}, intent, expectedContext}` | navigate only after Host flush/dirty guard; preserve selection/focus |
| `workspace.ui.contribute` | validated panels, outline trees, list/detail, form, search results, status, editor decorations, commands, review links | Host renders owned widgets; no guest HTML, React or CSS |
| `workspace.change.propose` | typed ChangeSet with operation IDs and evidence, expected read/write revisions | never direct write, approval, commit or publication |
| `workspace.derived.cache` | `{pluginId, snapshot, schemaVersion, config/modelDigest, key}` scoped get/put/evict | disposable, quota-bound; no Git/author-draft storage |
| `workspace.events.subscribe` | bounded revision/selection/visibility/activation signals | no indefinite polling; gap means re-read |
| `workspace.capabilities.query` | Host-side capability negotiation and precise unavailable errors | no silent fallback to different algorithm/model |

Implementation may collapse some of these into fewer WIT imports as long as typed behavior, versioning and isolation remain unchanged. Host must give model-independent lazy providers a separate lifecycle; no implicit model download for `repositories_list` or lexical search.

### Canonical type envelopes (logical JSON, WIT code generated from adopted schema)

~~~json
{
  "schema_version": 1,
  "request_id": "host-issued-request",
  "plugin_id": "proprium.narrative",
  "action_id": "proprium.narrative.hierarchy.tree",
  "scope": {"repository_id": 123, "branch": "main", "workspace_id": "opaque", "generation": "opaque"},
  "snapshot": {"id": "opaque", "local_commit": null, "worktree_generation": "opaque", "draft_generation": null},
  "input": {"parent_id": null, "limit": 128},
  "deadline_ms": 30000
}
~~~

`repository_id` follows the existing immutable GitHub numeric identity (other Git remotes need a separately typed provider ID). Workspace local IDs and legacy project IDs must not masquerade as the GitHub ID. Every response carries the observed snapshot; applied proposals return resulting snapshot and per-operation receipts.

**Action effects** are explicitly `read`, `propose` or Host-only `apply`. Plugin actions declare stable qualified IDs and JSON-schema/WIT input-output types; Host UI and MCP route through the same dispatch, validation, caps and errors. Adapter must reject unknown action IDs and extra input instead of parsing free-form prompt text as a mutation.

## Writer interaction contract

- Host-owned `OutlineTree` accepts ID/title/order/parent and invocation descriptors. Plugin supplies hierarchical data; Host handles keyboard, tree virtualization, reorder gesture and accessible non-drag alternative. Reorder produces a **proposal**, not a hidden Git write.
- Host-owned `ContextPanel` supports contextual sections, tab/breadcrumb, cite/evidence navigation, stale markers and a bounded preview. Plugin may register related entities, diagnostics and ChangeSet queue actions. Context follows selected scene/selection but MUST NOT replace text or force focus.
- Host-owned `DataTable`, `DetailEditor`, `ReviewPanel`, `Graph/Map/Timeline` presentation primitives can be introduced incrementally as actual recovered products demand them. Advanced Story Lens is a projection of Story Knowledge data, not an alternative canonical graph. If a visualization genuinely requires code-rendered pixels, use reviewed Host implementation or separately approved isolated iframe; do not grant untrusted plugin DOM access.
- The current Host `SceneEditor`, `RestoredEditor` and CodeMirror remain Host components. Narrative maps scene IDs and Markdown paths to this editor. A plugin cannot replace the editor's writable backing store.
- From a narrative title/scene selection: opening a scene MUST update the shared Host selection, activate the same manuscript, and preserve IME, caret, scroll/reading page, recovery and per-document editor instance when reference panels change. Mobile projection uses sheets and focus restoration, not desktop dock resized onto a phone.
- Plugin contributions appear in the **normal Host panel registry and presets**, not just `PluginPanel`'s output list. Removing a plugin yields a clear disabled/unavailable placeholder; generic Git continues.

## Snapshot/read and long-project scaling

Never force a user to fit hundreds of chapters/scenes into a single UTF-8 `RuntimeSnapshot`. The current limit (`256 files / 2 MiB / 128 KiB proposal file`) describes a *v1 implementation*, not the recovery acceptance for large works.

Readers list by path prefix and cursor, open selected file by pinned revision, stream or chunk long text with bounded bytes, and independently cache parsed work hierarchy and derived indexes. Scene navigation only needs the selected scene + adjacent hierarchy; distant Bible/reference data is lazy. A derived result is valid only for the exact repository, branch, worktree overlay, corpus/configuration generation, algorithm version and model digest (if applicable). A cache miss rebuilds in bounded work, never rewrites source.

## ChangeSet and recovery semantics

- Apply uses Host's sole local Git writer, exact expected versions and a declared set of paths. For inserts/reorders, the owning plugin compiles semantic intent and stable order/neighbor preconditions into generic file operations and complete read sets. The Host validates and applies file operations; it never interprets a scene schema.
- A proposed change must be visible as a complete diff, source quote/evidence and target paths before any bytes mutate. Partial approval preserves action boundaries; unsupported partial atomicity must be shown as unavailable, not faked.
- Review never reads a newer draft as if it were the proposal base. A dirty editor or changed scene makes a proposal stale/pending reconciliation; no silent overwrite, force publish, repeated idempotent effect or deletion of recovery entries.
- Host records a stable operation/proposal identity; retry after network loss fetches status/receipt before reapplying. Return status `proposed / approved / rejected / stale / applied / partially_applied / failed` and exact resulting commit/overlay identity as appropriate. None of those status names imply remote publication.
- Cancel/terminate Worker releases derived resources but leaves pending proposals and author data. Host is authoritative over approval, history, checkpoint, publish and rollback.

## MCP mapping

Current `/mcp` has eight constant built-in tools; do not reintroduce Client Token, Owner Key or per-client capability grants. A client calls `repositories_list` then uses `repository_id`/optional branch. To call an official authoring plugin, `plugin_call` resolves typed (`pluginId`, `operation`, `input`) through the installed and enabled action registry **in the active Browser Host**. The same typed result/proposal and the same actual repository scope are returned through UI and MCP; no separate Node Scriptorium `/mcp` runtime or duplicated action logic. If only the active repo supports a plugin renderer, report `repository_not_active` explicitly, never route to an arbitrary repo.

Externally authenticated MCP clients can *propose*, not approve. Browser Host authors see complete proposal contents in their current UI. Explicit approval is not equivalent to commit or GitHub publish.

## Required error taxonomy and security

`invalid_input`, `unsupported_schema`, `repository_unavailable`, `scene_not_found`, `missing_capability`, `plugin_unavailable`, `snapshot_stale`, `conflict`, `unapproved`, `capacity`, `cancelled`, `timeout`, `storage_unknown` and `publication_unknown` are distinct machine-readable results. The UI gives a retry or recovery path and preserves source text. Never return a fake successful empty result.

Each guest runs under verified publisher signature/digest and explicitly approved capability intersection. No guest-provided JavaScript/CSS/HTML in the Host origin, broad network, Git credentials, arbitrary filesystem or unscoped storage. Context transmission to an external LLM is a separate consent/scope decision from reading local files or enabling a plugin.

## Host contract acceptance (before any plugin can be declared complete)

1. Signed official plugin installs, contributes **a functional outline/form/command**, operates on a synthetic Arcadia work via paged reads, and survives Host reload without a rebuild.
2. Same plugin's actions are callable via UI and `plugin_call` with the same schema and revision, against explicitly selected repo. Missing/disabled plugin produces typed unavailable.
3. Hundreds of synthetic scenes across more than 256 files can be listed and one scene edited without full-repo import or hidden byte-limit failure; partial/data fetching is bounded.
4. Bad path, stale snapshot, unknown publisher, unauthorized import, malformed descriptor and lost client/Worker cancel all fail closed without deleting Draft/Checkpoint.
5. A plugin proposal is reviewed (including reject/partial approve), applied only at current revision and **never auto-published**; the active editor remains mounted on Desktop and Mobile.
6. Disable/remove/rollback releases Workers, retains author data, leaves the plain Git file editor operable and maintains deterministic missing-panel fallback.

## H0 authoring profile v2 (fixed logical schema)

The following is the **fixed v2 authoring contract**. Its incompatible `proprium:plugin@2.0.0` WIT transport is implemented in `app/src/browser/proprium/plugin-runtime/wit-v2/main.wit` with Host-validated typed JSON exchanges in `plugin-runtime/v2/`; it does **not** modify the v1 WIT file. The logical schema and Host operations are implemented incrementally and require per-operation conformance evidence; optional provider-backed capabilities remain conditional on admission, consent and available assets. Field spellings below are logical JSON; plugin-specific payload fields are defined in the owning canon. Omitted optional fields are absent, never inferred from another workspace. Unknown input fields fail `invalid_input`; unknown source-file fields are retained.

### Identity, content and errors

| Type | Required fields / semantics |
| --- | --- |
| `Scope` | `workspace_id:string`, `repository_id:positive integer\|null`, `branch:string`, `generation:string`. Null repository means an unbound local Git workspace; MCP remote calls require a numeric binding. Binding/changing a remote increments generation and invalidates leases; legacy project/work IDs are domain IDs only. |
| `Snapshot` | `id:string`, `local_commit:string\|null`, `worktree_generation:string`, `draft_generation:string\|null`. Host issues opaque identifiers after pinning the directory view. A missing local commit is valid for an unborn repo. `remote_commit` is optional observed remote provenance, never the read base. |
| `FileRevision` | SHA-256 of exact file bytes; `null` means absent at this snapshot. A zero-length file has a hash, not null. Paths are normalized relative UTF-8 paths, no absolute path, NUL, backslash, empty/`.`/`..` component or symlink traversal. Never normalize distinct case-sensitive paths into one identity. |
| `SourceSpan` | `path`, `revision`, `start:number`, `end:number`, `quote:string`. Offsets are half-open UTF-16 code units in decoded, unnormalized text; `0 <= start <= end <= text.length`. Validate quote before source navigation. Normalized/tokenized text must retain a source-offset map; never use UTF-8 byte offsets as editor positions. |
| `ActionRequest` | `request_id:string`, `plugin_id:string`, `action_id:string`, `schema_version:1`, `scope`, `snapshot`, `input:object`, `deadline_ms:integer`, `idempotency_key?:string`. Host supplies caller `ui\|mcp\|plugin` and activation epoch out of band; guests cannot assert a user gesture or caller identity. |
| `ActionResult` | Discriminated `{ok:true,request_id,scope,snapshot,value,warnings:[]}` or `{ok:false,request_id,scope,snapshot,error:{code,message,retryable,details?}}`. Errors contain no secrets. A typed partial-coverage value names omitted paths/reasons; empty success never hides unavailable data. |
| `ActionDescriptor` | `plugin_id`, `action_id`, `schema_version`, `effect:read\|propose`, input/output schemas, required capabilities, `callers` subset of `ui,mcp,plugin`, `requires_user_gesture:boolean`. Qualified action IDs in each canon are immutable; legacy IDs are explicit adapters, not a second implementation. |

`read` includes bounded pure analysis and disposable cache/index writes, never canonical file mutation. Navigation, downloads, consented provider requests and share-secret reveal are separately gated Host effects; declaring `read` cannot authorize them. `propose` only returns a Host-owned proposal reference and preview. `apply`, save, recovery, checkpoint, publish, enable/grant and credential operations have no guest action or MCP approval endpoint. Source-specific legacy errors map to the common error envelope and retain the original code in `details.legacy_code`; `snapshot_stale` is the public stale error (legacy `stale_precondition` maps to it), and `cancelled` is public (`canceled` from v1 maps to it).

Required additional errors: `capability_denied`, `invalid_path`, `invalid_encoding`, `file_not_found`, `unsupported_format`, `ambiguous_identity`, `dirty_draft`, `dependency_unavailable`, `provider_unavailable`, `external_state_unknown`, `artifact_too_large`, `idempotency_conflict`, `incompatible_abi`, `guest_trap`, `repository_not_active`. `retryable` authorizes a new user attempt, never automatic mutation or paid-service retry. UI shows the preserved input and the relevant retry/review path.

### Pinned partial reads and event flow

`file.list({snapshot,prefix,cursor?,limit=128})` returns `{entries:[{path,revision,byte_length,media_type}],next_cursor:null|string}` in UTF-8 path-byte order. Max limit 256. Cursor binds snapshot+prefix; changing either is `invalid_input`. Directory absence returns an empty list; unreadable scope returns an error. Host pins the listing and byte reads together: it either retains immutable bytes or returns `snapshot_stale`; mixing new bytes into the old snapshot is forbidden.

`file.read({snapshot,path,offset=0,length=65536})` returns `{revision,total_bytes,offset,bytes,next_offset:null|integer}`; byte ranges are nonnegative and at most 256 KiB, beyond EOF is invalid. UTF-8 is decoded incrementally across chunks, without stripping BOM, frontmatter or changing CRLF. Binary reads remain bytes. Text parsers report `invalid_encoding` with path; they do not silently skip a malformed canonical file. Missing content reports `file_not_found`, including when offline. Scopes above 256 files / 2 MiB remain valid; no total-repo eager load is permitted.

Draft text is a separate Host lease. Default reads are saved worktree bytes; a user may explicitly include a current draft, producing a new snapshot with `draft_generation`. Results and exports disclose draft inclusion. Such results cannot be applied to saved bytes without fresh reconciliation. Plugin reads never flush, checkpoint or publish the draft.

`events` contain `{sequence,scope,snapshot,kind,paths?}` where kind is `files_changed|selection_changed|visibility_changed|revoked`. Selection text is provided only under a scoped grant. Sequence gaps invalidate derived views; consumer re-reads and never assumes no change. Host registry dispatch forwards the same scope/snapshot, intersects caller and callee grants, and records an invocation stack; recursive action dispatch is rejected. Optional enrichment consumes already returned values, never calls back into its consumer.

### Complete generic proposal and apply protocol

A `ChangeSet` is `{id,idempotency_key,scope,snapshot,title,reason,read_set,units,evidence}`. `read_set` is a unique-path array of `{path,revision}` including absence preconditions and every hierarchy/source file used to compute output. `units` is an ordered array of `{id,label,depends_on:unit-id[],operations:[]}`; dependencies form a DAG. An operation is `{id,kind:create|replace|delete,path,expected_revision,content?:byte[],content_artifact?:string}`. Create requires null revision; replace/delete require existing hash; non-delete requires exactly one of inline `content:byte[]` or a sealed `content_artifact` ID, while delete permits neither. No operation targets the same path twice within a unit. A move compiles to source deletion + destination creation in one unit, with references included in that unit. Domain-specific patches, IDs and neighbor preconditions are checked by the plugin at proposal generation and bound through complete file read revisions; Host does no story-domain parsing.

Host review presents byte/text diff, create/delete, dependencies and evidence for each unit. Selective approval chooses whole units plus their dependency closure; splitting an inseparable unit is unavailable. Immediately before applying, Host locks the workspace writer and revalidates scope, the original worktree generation (including directory membership), every read revision, every write precondition and dirty buffers. Unrelated worktree changes also require a refreshed proposal in this v2 baseline; no incomplete list read can miss a concurrent newly created sibling. Any mismatch returns `snapshot_stale` or `dirty_draft`, retains draft and proposal, and requires new review after rebase. No automatic merge or string concatenation. Reject changes no file.

H0 requires a recoverable write-ahead receipt for each unit with old/new content hashes, staging paths and operation IDs. Stage all bytes before exposure; after interruption verify and finish or restore that unit before allowing another writer. If recovery cannot establish a unit, return `storage_unknown` and block mutation pending Host verification. Never claim cross-file atomic visibility without adapter proof. Multiple selected units may yield `partially_applied`; receipt names completed/failed/pending units and exact revisions. It never labels a partial set applied. Apply updates the local worktree only; checkpoint and publish remain separate Host gestures.

Idempotency is scoped to workspace+plugin+action+key and canonical request digest. The same key/digest returns the original proposal/receipt; different input returns `idempotency_conflict`. Host journals proposal/receipt before reporting success and queries it after lost responses. Unknown recovery state must be resolved before retry; no duplicate append or uncertain replay. Rejected/stale proposals remain inspectable until explicit user dismissal, and disabling the producer preserves receipts. Cancellation before apply prevents apply; cancellation during a Host write waits for its recoverable unit boundary and reports actual state.

### Functional UI protocol

Every declaration has `{id,kind,title,context,body}` and stable row/entity IDs. `body` is a validated tree of Host widgets: `outline`, `list`, `table`, `detail`, `form`, `tabs`, `status`, `progress`, `evidence`, `diff`, `graph`, `map`, `timeline`. Nodes use text values, column/field schemas, bounded rows, paging tokens and action bindings `{action_id,input_template}`; no expressions, HTML, JS URLs, React or global styles. Only declared data-key substitution is allowed. Forms support string, integer, boolean, enum, multi-reference and ordered-list fields, validation messages, submit/cancel and pending values. Graph/map/timeline accept positioned entities/edges/time ranges plus text table equivalents; no publisher canvas code. Diagnostics/decorations are version-pinned noneditable annotations. Host owns all rendering and text escaping.

Host validates action availability/schema/caller and disables unsupported controls with reasons. Loading, ready-empty, partial, stale, unavailable, failure and submitting are distinct visible states. Every panel includes an accessible title, close/back, focus restore and an editor-return target. Desktop tree arrows/Home/End, Enter open, Space select and reorder buttons have touch equivalents. Escape closes only the top sheet/dialog; while IME composes it does not navigate, submit, accept changes or discard text. Commands appear in the Host command palette; plugin shortcuts require Host conflict checks and cannot override editor composition. Mobile uses task sheets with explicit Apply/Cancel, no drag-only operation. Switching a reference panel never remounts CodeMirror or changes its document identity.

Navigation request is `{target:{path,span?,panel_id?},expected_context:{scope,snapshot,document_path?,draft_generation?},intent:open|reveal|return}`. Guest scene IDs are descriptive metadata; the owning plugin resolves them to validated paths. Host defers document transitions until composition ends, retains per-document journal/undo/caret/selection/scroll, and offers stay/save-local/leave-with-retained-draft when needed. Failed save keeps the original editor active. Missing/stale targets show a refreshable error and never open another file by guessed ID. `return` uses a Host-issued opaque return token, not a plugin-stored editor instance.

### Artifact delivery, external providers and consent

Host artifact capability is `artifact.create({media_type,filename,scope,snapshot}) -> artifact_id`, `artifact.append({artifact_id,sequence,bytes})`, `artifact.seal({artifact_id,sha256,total_bytes})`, `artifact.discard({artifact_id})`. Max chunk 256 KiB, total default 128 MiB per job, one in-flight artifact per plugin; exact negotiated limit is visible before export. Sequence is contiguous and duplicate chunks must match their hash. Quota/size/seal mismatch discards incomplete output with typed error. A sealed artifact is immutable, scoped and usable for a proposal or a **Host user-initiated** download; MCP receives metadata/hash/availability, never an automatic download/print or secret. Host releases temporary artifacts on cancel, workspace change or after explicit download/dismissal; Git bytes are unaffected. Large EPUB/text uses this sink rather than whole-base64 RPC. No export is a Git push.

Optional `provider.request` is a **DESIGN_TARGET Host broker**, independent of Gateway. Input is `{request_id,provider_id,model_id,purpose,payload,source_manifest,max_output_bytes}`. Host shows exact destination/content scope and estimated cost if known, obtains an explicit request consent and uses a Host credential handle. Plugin never receives tokens or browser credentials. Endpoint/model allowlist and credential state remain Host-local, default-deny; Git settings and legacy consent records cannot grant network authority. Default output cap 1 MiB and deadline 120 seconds; user can cancel, a lost paid-service response is `external_state_unknown` and is not auto-retried. Missing broker/consent is `provider_unavailable`/`capability_denied`; external MCP LLM and provider-free local helpers continue independently. Responses are untrusted suggestions tied to their original snapshot, not approval or file writes.

Shared secret reveal/service mutations additionally require descriptor `callers:[ui]` and verified user gesture. Host keeps bearer values out of action transcripts, Git, caches and MCP results. Publishing canon defines exact service availability; Gateway never becomes durable share storage. No content egress is authorized merely by enabling a plugin.

### Resource and lifecycle defaults

Host negotiates limits before activation. Baseline: one Worker and one active job per plugin, at most four active compute jobs per workspace, 1 MiB normal action input/output, 256 KiB RPC chunk, 30-second interactive job deadline, explicit batch jobs up to 120 seconds. A long corpus job checkpoints derived progress between bounded batches and resumes only from an exact scope/config cache key; it cannot block typing. Progress is at most 10 messages/second, event queue 256 entries then a gap marker. Derived cache defaults to 64 MiB/plugin; explicit model/asset budgets are separate, disclosed and consented. Device quotas may be lower and return `capacity`; no fabricated mobile fallback or hard memory isolation guarantee.

Disable/update increments activation epoch, rejects late messages, cancels jobs, disposes/terminates Worker, closes provider leases and releases models/artifacts; it preserves author files, Host drafts, proposals and receipts. Models/dictionaries are signed manifest assets with digest, size, license and tokenizer/algorithm version; no weights are fetched at enable-idle. Missing optional capability disables only its feature. A verified staged upgrade activates only after old jobs drain/cancel and schema compatibility is established; failed upgrade retains the admitted previous version under current registry policy.


### Optional cross-workspace reads and preferences

`workspace.repository.snapshot.read` accepts `{workspace_id,repository_id,branch,snapshot_id}` selected from Host-registered local bindings. Host requires separate user-selected scope, pins that workspace's bytes and grants the caller read-only list/read leases. Missing binding, unavailable offline bytes or unapproved scope returns an error; no implicit clone, token, fetch or widening of current workspace. Cross-work sources join the proposal read set with their scope and must be revalidated at review. An inactive remote workspace cannot be written through this capability. Series overlays name every source snapshot and preserve conflicts rather than selecting a silent winner.

`plugin.preferences` stores nonsecret browser-local `{plugin_id,user_partition,key,schema_version,value}` via Host, default 64 KiB/plugin, distinct from the disposable derived index. Allowed values include reranker opt-in, chosen view and local filters. It cannot store manuscript/corrections, provider credentials or substitute for capability consent. Unsupported/corrupt settings fall back to a declared safe default; disabling retains preferences and revokes execution. Uninstall offers explicit local-preference removal while never deleting Git source. No polling or worker is needed to read preferences.

`artifact.preview_text({artifact_id,return_token})` is a Host-only UI operation over a sealed UTF-8 artifact. Host streams bytes into its escaped text/ruby/vertical-print renderer, paginates without loading a second whole-book string into an action result, and opens print only on a fresh user gesture. Invalid UTF-8 and oversized print layout report errors with original artifact retained for download; artifacts cannot supply HTML, script, CSS or executable print templates. Close/cancel returns through the original editor token with Draft/IME state intact. MCP and plugins receive metadata only and cannot open print UI.

Preference controls bind a declared plugin-namespaced key and value schema to a Host UI widget. The Host validates and stores the changed value on a user gesture; this is a local UI action, not a guest `propose` or Git ChangeSet. A guest may read validated current preferences, but cannot mutate them through `read` or claim consent. Legacy settings actions that used to change per-user model/reranker preferences become explicit adapters to this UI route; non-UI callers can read status and receive `capability_denied` for changes.

### Secret tokens and read-only reader routes

The Host-only `secret.token.create({purpose,scope,expires_at})` requires a current UI gesture and creates 32 cryptographically random bytes, encoded base64url without padding. `sha256` is lowercase hex SHA-256 of the encoded bearer string in UTF-8, matching the existing grant format. The guest receives `{handle,sha256}` only; the Host retains the secret in a one-use reveal buffer. `share.token.create` is Publishing's scoped binding to that operation. The Host associates the buffer with the exact proposal and reveals only after review/apply, warning that public availability requires remote confirmation. Reject/cancel/expiry clears the buffer. Reload before reveal cannot reconstruct it; create a fresh revocation/replacement proposal. The raw bearer is never in Git, plugin input/output, MCP, history, telemetry or cache. A displayed link is a deliberate owner copy action; shared-browser persistence is not promised.

The static Host's generic `readonly-reader` declaration binds a plugin ID, a fixed Host-rendered read-only layout and an admitted provider interface. Publishing uses `/r/publishing/{repository_id}/{grant_id}#token={bearer}`. The Host extracts the fragment into a secret lease, removes it from address-bar history before network calls, and sends it only in the configured TLS reader adapter's authorization header. No guest-defined executable route, HTML, DOM or auto-activation of workspace plugins is allowed. Reader pages do not open the owner's editing workspace or expose drafts, Git credentials or private browser storage; they render only confirmed remote data authorized by that adapter. The provider capabilities/metadata/ranged-scene contract and revocation checks are fixed in [Publishing](plugins/PUBLISHING.md). Unsupported/missing provider renders an unavailable reader, never a false public preview of local files. Clear the bearer lease on exit.

### Mixed-domain compilation without a second writer

Paired Writing preserves the nine pinned NarrativeChangeSet v1 operation kinds through public read-only compilers `proprium.narrative.changes.compile` and `proprium.knowledge.changes.compile`; its own manuscript compiler handles `manuscript.replace-range`. Input is `{operations:[source-v1-operation],evidence:[source-v1-evidence],staging_snapshot?:string}` within the shared request's original scope/snapshot. Output is `{read_set:[{path,revision}],units:[generic-unit],operation_map:[{source_operation_id,unit_id,operation_ids:[]}],diagnostics:[{code,path?,message,severity}]}`. Validation errors fail the call; diagnostics never conceal rejected operations. The exact source v1 key/type/bound rules are pinned in `modules/story/src/narrativeChangeSet.ts:validateOperation/validateEvidence`; source IDs map to verified workspace scope, never legacy server authority.

Narrative compiles structural volume/chapter entity create/update, `scene.create`, `scene.insert` and scene structure/manuscript-link/order and Narrative reading-mark changes. Knowledge compiles other entity create/update, semantic scene-field changes, `state.append-event`, `thread.link-scene`, `reference.link`. A `scene.update` with both sets of fields is split into two compiler calls carrying one source operation ID and one inseparable final unit. ID/type mutation is invalid. Each compiler shares its own public propose action's validator/patch generator; it does not call `workspace.change.propose` or acquire write authority. Missing owner returns `dependency_unavailable` with retained original input.

Host's generic `workspace.change.stage({base_snapshot,previous_stage?,units}) -> {staging_snapshot}` checks file preconditions, overlays the exact generated bytes in ephemeral quota-bound memory/storage and returns a read-only lease. It does not modify worktree/editor/Git, generate a commit or count as approval. Lease is bound to caller chain, original scope and snapshot; it cannot cross workspace or survive cancellation/reload. Ordinary plugin read APIs can read that lease only in this orchestration, keeping original-path provenance. Paired processes source operation order, gives later compilers this staging snapshot, and unions original-base path revisions (including absent paths). A later edit to an earlier staged file depends on that earlier operation, not a fictitious saved file revision.

Before proposing, Paired collapses repeated staged writes to the same path into one original-base -> final-bytes operation, keeping the complete semantic operation map/evidence and original read set. All operations connected by path overlap, created-ID references or declared dependencies form one inseparable unit; independent components are separately selectable units in original order. Cyclic explicit source dependencies fail `invalid_input`; staged forward references not resolvable in source order fail with the exact source operation ID. A review includes every intermediate semantic intent and final file diff. One generic Host ChangeSet is registered only after every compiler succeeds. Apply revalidates the original base; staged bytes never bypass stale/dirty checks. Retry reconstructs or reuses the same idempotent proposal receipt; it never reapplies an uncertain set.

Foreign read preconditions use `{scope,snapshot,path,revision}` within `read_set`; local entries may omit `scope/snapshot` and inherit the ChangeSet base. Host grants and revalidates each foreign lease explicitly, and rejects foreign writes. Read-set uniqueness is by scope+snapshot+path rather than path alone. Unavailable foreign bytes yield `repository_unavailable`, not an ignored precondition. Generic staging snapshots are Host-issued opaque IDs over that original base; Host read adapters resolve the ID to overlaid exact bytes and never accept a guest-constructed snapshot object as a staging lease.

### Registry discovery and proposal receipts

The registry provides Host metadata operation `actions.list({plugin_id,cursor?,limit?:1..100}) -> {items:ActionDescriptor[],next_cursor}` without creating a Worker. It returns only installed signed declarations filtered by caller, with `availability:ready|disabled|dependency_unavailable|capability_denied|incompatible` and the reason. In the existing fixed `plugin_call` MCP tool, reserved `operation:"actions.list"` uses this Host metadata route; other operations are exact public action IDs, schema-validated under that installed plugin. The current v1 `operation:"run"` remains explicitly v1 and cannot masquerade as v2 typed dispatch. `discover_actions` is recovered through this route, not a ninth Gateway tool or execution of a guest prompt.

Host receipt read capabilities use the request's selected scope, read authorization and caller policy. `workspace.change.list({cursor?,limit?:1..100,status?}) -> {items:ProposalStatus[],next_cursor}`; `workspace.change.status({proposal_id}) -> ProposalStatus`; `workspace.change.observations({proposal_id,cursor?,limit?:1..100}) -> {items:ReceiptEvent[],next_cursor}`. Default limit is 50. A missing proposal is `file_not_found` with `details.kind:"proposal_not_found"`; a stale cursor is `snapshot_stale`. Reads do not approve, retry or modify receipts and have no implicit network request.

`ProposalStatus` is `{proposal_id,source_id?,source_payload_digest?,producer_plugin_id,scope,base_snapshot,status,submitted_at,units:[{id,source_operation_ids,depends_on,status,resulting_revisions:[{path,revision}],failure?}],approved_unit_ids,checkpoint:{local_commit,remote_commit,remote_confirmed},source_payload_available:boolean}`. Status is one of `proposed|approved|rejected|stale|applying|applied|partially_applied|failed|storage_unknown`; commit fields are nullable and false by default, and a local apply never changes `remote_confirmed` to true. Missing/incomplete retained source payload is explicit and cannot be reconstructed or replayed from a digest. `ReceiptEvent` is `{sequence,at,kind:submitted|reviewed|rejected|apply_started|unit_completed|unit_failed|recovered|checkpointed|remote_confirmed,proposal_id,unit_id?,snapshot?,resulting_revisions?,error_code?}` with monotonic sequence per proposal and Host-issued timestamps. Egress secrets/full provider responses are excluded. Paired's read-only facade exposes only these permitted values; the Host remains the receipt authority. Uncertain local storage returns `storage_unknown` rather than an empty history.

### Signed v2 declarations

Typed offline discovery requires signed declarations, not guest startup. The authoring manifest is `schema:"proprium.plugin/v2"`, `abi:"proprium.component/v2"`, with the current immutable `id`, `version`, `entrypoint`, `capabilities`, `artifacts` fields plus `actions:ActionDescriptor[]`, `ui:SurfaceDeclaration[]`, and `asset_groups:AssetGroupRef[]`. These three arrays may be empty. Manifest ceiling is 512 KiB; IDs and byte/path/digest validation retain the existing strict rules. Artifact/publisher signature and registry delegation remain Ed25519 over exact bytes as in the existing distribution contract. Dependencies stay in signed registry metadata with resolved pins, never inferred by executing code. V1 admission is unchanged; the v2 parser rejects missing/unknown mandatory fields. Runtime UI can bind new scoped data only within the signed surface/action declarations, never register undeclared privilege or caller permissions.

Input/output JSON Schemas are Draft 2020-12, closed object shapes (`additionalProperties:false`) with bounded arrays/strings/integers; `$ref` may target only digest-bound JSON schema artifacts in this manifest, never network URLs. Manifest action IDs are unique. Descriptor `schema_version:1` refers to the payload contract, independent of WIT/package/manifest versions. Generated WIT adapters and schema validators must conform to these exact field/effect/caller semantics; schema reference resolution does not fetch arbitrary documents.

A model/dictionary group is an optional immutable signed asset manifest referenced by `{id,manifest_path,sha256,bytes,role:dictionary|embedding|reranker}`. Its manifest describes `{schema:"proprium.assets/v1",id,version,license,files:[{path,bytes,sha256,chunks:[{path,offset,bytes,sha256}]}]}`. Chunks are contiguous, nonoverlapping, at most 16 MiB; offsets cover exactly the declared file size. Paths use the same safe relative rules. Host verifies the signed parent reference, every chunk and whole-file digest before a model lease; reconstruction is private derived artifact data, never Git. The base plugin bundle retains the existing 128 MiB/asset and 512 MiB/bundle ceiling; separate optional model groups do not auto-download during installation or activation. Host shows exact total group bytes/storage/device requirements and obtains explicit capacity consent before group transfer. Embedding/reranker groups are independent, so a multi-gigabyte reranker can be unavailable without rejecting the small plugin or embedding group. Inadequate storage/memory is `capacity`, and no mobile/desktop model support is claimed until measured. Signed asset metadata records redistribution license/provenance; third-party model bytes are not part of this canon change.

`workspace.change.inspect({proposal_id,cursor?,limit?:1..50,include_source?:boolean})` is the read-only proposal-body view. It returns `{proposal_id,status:ProposalStatus,title,reason,read_set,units:[{id,label,depends_on,operations:[{id,kind,path,expected_revision,content_ref?,before_hash?,after_hash?}]}],evidence,source_payload?,next_cursor}`; default page size 20. `source_payload` is the preserved versioned domain input (for Paired, the exact NarrativeChangeSet v1), included only when requested and within caller read permission/normal RPC cap. Larger source payloads use an immutable scoped `source_ref` with byte length and digest instead of truncating silently. `content_ref` identifies proposed exact bytes, not a downloadable executable URL. `workspace.change.content.read({proposal_id,ref,offset=0,length=65536})` returns `{offset,total_bytes,bytes,next_offset,sha256}` with max 256 KiB chunks, current read authorization and immutable receipt scope. Content-ref/source-ref access never mutates a file or opens download/print. Host escapes text and computes its review diff from these same bytes. Secret reveal/provider-credential material is excluded before any proposal exists, so this read cannot expose a share bearer. Missing retained source is an explicit `source_payload_available:false` and `file_not_found` for a requested payload; the Host never reconstructs a fabricated source ChangeSet. This preserves legacy `get_change_set` inspection through the existing `plugin_call` facade without adding approval authority.

Caller policy defaults for this authoring profile are fixed: public pure-read and file-proposal actions declare `callers:[ui,mcp,plugin]` so admitted consumers can use their typed contracts; the Host still intersects source scope and both parties' grants. Explicit narrower declarations in an owning canon take precedence. Narrative hierarchy/scene context and Knowledge/Research exported read capabilities must include `plugin`, as required by the DAG. Owner `changes.compile` descriptors are `callers:[plugin]` with an additional caller-plugin allowlist containing only `proprium.paired-writing`. Share secret operations, per-user preference mutations, portable-position capture and explicitly UI-only settings actions require `ui` plus a verified fresh user gesture. A plugin/MCP-origin provider request still needs separate Host author consent for the exact outbound payload and cannot manufacture that consent. Returned navigation intents never open a document for a non-UI caller.


A sealed artifact referenced by a proposal changes ownership on successful proposal admission: Host verifies the digest, retains exact bytes in its receipt/recovery store, and journals the proposal reference before returning success. It is no longer a plugin-temporary export. Disable, guest cancellation, workspace switch or asset-cache eviction cannot remove content needed by a pending/applied receipt. Proposal dismissal/Host retention policy may release it only after no recoverable receipt references it. Failed admission returns a typed error and status/idempotency lookup determines whether ownership transferred; never report a reviewable proposal with missing byte content. This exception is required by the general artifact-cleanup rule and makes multi-file proposals recoverable without a running producer.
